## 2. 새로 재현한 잠재 수식 구분 예외 — 기존 LIVE의 오류로 확대해석 금지
- 원문에서 ` · `는 대개 개별 요소 구분기호이지만, 공백 있는 식 `x = a · b + c · d`의 곱셈점이기도 함.
- 기존 splitter에 합성 예시 `내적식 x = a · b + c · d · 계산 결과 검증 · 적용 확인`을 주면 수식의 곱셈점까지 분리 후보가 되고, 짧은 단독 문자 `b`·`d`가 포함되어 전체 목록이 `null` 폴백됨. **원문 손실은 없지만 수식 뒤의 정상 X/Y 요소별 독립 목록 표시가 생략되는 가시성 문제**.
- LIVE 3,800개 학습대상 X/Y 7,600셀을 읽어 해당 명시적 등식 + 공백 곱셈점 후보를 점검했으나 **현재 매칭 사례 0셀**. 따라서 현재 LIVE에 같은 결함이 실제 발생했다고 보고하지 않음.
- 수정은 기존 공백 ` · ` 감지 분기에서만, `=`/전각 등호 이후 이어진 **명백한 단일 영문자 또는 숫자 피연산자** 사이의 곱셈점만 구분자로 취급하지 않도록 하는 좁은 조건. 명확하지 않은 다른 기술명이나 문장에서는 기존 보수적 판별 유지.
