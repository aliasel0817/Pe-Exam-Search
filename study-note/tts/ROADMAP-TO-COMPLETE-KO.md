## 고정 읽기 정책

토픽명(항상 읽음) → 개념 → 등장배경 → 필요성 → 특징 → 기술요소/구성요소 → 키워드.
본문 6개 항목은 사용자가 선택. 기본값 전부 읽기. 공란은 건너뜀. 암기법·관련토픽·추가 읽기는 없음.
각 토픽 및 필드 별 공유 MP3 1회 생성 후 재사용: **음성 합성 반복 비용 절감**. GCS 저장·전송·Cloud Run 요청 비용은 별도.

## 완료 기준의 두 범위

**기능 출시**는 1~6 및 8 중 핵심 멀티디바이스 QA 통과 후 소량 토픽으로 가능.
**전 토픽 음성 라이브러리까지 완료**하려면 7단계 전체 학습대상 Y 커버리지·오류 검증까지 필요.
초기 배포와 3,800건 전체 음성 생성은 비용·소요 기간이 매우 다르므로 각각 별도 승인.

## 즉시 다음 작업 (2단계: 음성 파일럿)

Google 로그인 단계가 성공하여 동일한 테스트 페이지 반복 사용 불필요. 개발 브랜치에서 다음 작업을 진행:
1. Cloud Text-to-Speech Chirp3-HD 세 종류 목소리, 발음 사전, 7필드 음성 분리 생성 로직의 무료 DRY RUN 점검.
2. 대표 토픽 샘플 3~5건을 사용해 글자 수/UTF-8 크기/청구 가능 호출 수 미리 계산.
3. 공식 Google Cloud 가격·무료 제공량·쿼터를 다시 확인.
4. **실제 음성 생성 요청은 사용자 비용 동의 및 생성량 상한 확정 이후 실행.**
5. GCS MP3 업로드도 별도 승인 전에는 실행하지 않음.

## Cloud 제어 원칙

- 예산 알림은 과금 상한 아님; Cloud Build·Cloud Run·GCS 스토리지·전송·Logging이 청구될 수 있음.
- 반복 합성 대신 필드별 MP3 영구 재사용; 토픽 본문 변경 때 해당 세그먼트만 hash 검증 후 업데이트.
- Cloud Run 게이트웨이 1개 현재 배포, 무인증 HTTP 401과 GitHub Pages CORS HTTP 204 확인.
- **추가 Cloud Run 리비전 배포**는 `cloudRunRevisionUpdateUserApproved=false`로 별도 승인 전 금지.
- **실제 AI TTS 생성**은 `ttsGenerationApproved=false` (별도 동의 전 금지).
- **MP3 GCS 업로드**는 `gcsUploadApproved=false` (별도 동의 전 금지).
