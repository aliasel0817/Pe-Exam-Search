# 학습노트 다중 기기 동기화 — 8단계 공통 작업계획·검증표 (v1.0)

> 적용일 2026-11-13 KST. 엔지니어링(조사·설계·개발·통합·UI) : 검수·배포 게이트 = **80 : 20**.
> 각 단계 끝에는 완료 증거 + 다음 단계의 완전한 독립 실행 요청서를 작성한다.

## 절대 준수 규칙
- LIVE MASTER `암기장` 원문·학습정보·PDF·첨부파일·주석·기존 기기 IndexedDB를 승인 없이 변경/삭제하지 않는다.
- 현재 `main`·운영 브라우저 소스·운영 Apps Script·미병합 PR을 단계 시작 시 재확인하고 기준 Commit SHA를 기록한다.
- 수정은 별도 브랜치와 Draft PR, 운영 main 병합·배포는 별도 명시적 사용자 승인 후에만.
- 다른 채팅의 원격 PC·프로세스·PID·Git 작업을 건드리지 않으며, 작업 소유권/절대 경로 불명 시 코드 변경 금지.
- 시트 신설/변경은 승인된 명확한 스프레드시트 ID 확인 후; Stage 3부터 먼저 격리된 시험용 사본에서 검증.
- 자동 검사 PASS와 PC·태블릿·스마트폰 실제 조작 PASS는 혼용하지 않는다. 수동 실기기 미확인 시 명시.
- 원래 기능을 축약·삭제하거나 인증 우회, 데이터 리셋, 임의 last-write-wins 적용 금지.

## 8단계 배분 (전체 노력 100 단위)

| 단계 | 작업 | 세부 체크 수 | 노력 비중 | 완료 게이트 |
| --- | --- | ---: | ---: | --- |
| 1 | 현황·LIVE 구조·PR·기존 기록·인증 기준선 | 4 | 8% | 증거가 있는 분석보고 + 위험목록 + 다음 요청서 |
| 2 | 공용 스키마·충돌 정책·동기화 프로토콜·롤백 설계 | 4 | 10% | API·DB 명세, 최초 병합 시나리오, 승인/보류 조건 |
| 3 | 서버 Apps Script API + 별도 동기화 시트(격리 개발) | 5 | 20% | 인증/락/버전/기본 저장 확인, 운영 무변경 |
| 4 | 웹앱 IndexedDB 변경 추적·업로드/다운로드·오프라인 | 5 | 21% | 여러 기기 상태의 논리적 수렴 및 동기화 버튼 연동 |
| 5 | 기기별 기존 계획/진도 백업·최초 통합·충돌 복구 | 4 | 14% | 삭제 없이 dry-run, 대조표, 복원 가능 |
| 6 | UI·상태 안내·기존 백업/복원 설명 개정 | 3 | 7% | 기존 학습 메뉴 레이아웃 유지, 정확한 문구 |
| 7 | 핵심 자동·브라우저·권한·오프라인·다기기 회귀 | 4 | 15% | 필수 8~12 시나리오 PASS/미확인 구분 |
| 8 | 승인 게이트·PR 병합·Pages/Apps Script 배포·운영 확인 | 3 | 5% | 승인 증거·배포 SHA·운영 경로의 실제 응답 일치 |
| **합계** | | **32** | **100%** | **개발/설계 80 : 검수/배포 20** |

노력 비중은 시간 약속이 아니라 전체 작업 우선순위·범위 배분을 위한 상대값이다.

## 최소 재확인 규칙
1. 단계 시작 시 이 기준선, 이전 단계 인계, 최신 main, 현재 미병합 PR 먼저 읽는다.
2. 코드가 변했다면 기준선을 새 커밋에 맞춰 대조하되 기존 실사용 원본을 덮어쓰지 않는다.
3. 상태를 검증할 수 없는 부분은 '미확인'으로 기록하고 가정과 사실을 분리한다.
4. Stage 8 전에는 승인 없는 운영 main 병합·배포를 하지 않는다.
