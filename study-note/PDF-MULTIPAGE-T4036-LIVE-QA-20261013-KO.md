### 잠재 위험 및 주의
1. **페이지별 업로드는 한 번에 원자적 트랜잭션이 아님.** 3페이지 중 2페이지만 성공하면 일부 신규 Drive 파일이 남을 수 있음. 같은 관리창에서 오류 메시지를 확인하고 저장 재시도.
2. **최신 Apps Script 버전 전체에 대해 업로드 계약 직접 검증을 완료한 것은 아님.** 신규 원본 2페이지와 관련 API 경로의 호환성은 실서비스 증거로 확인됐지만 보강·개정·교체 경로는 별도 시험 필요.
3. **모바일 큰 파일 처리 한계.** PDF 분할 메모리 부하가 발생할 수 있어 초기 검증은 2~3페이지 PDF로 한정.
4. 테스트를 이유로 기존 운영 PDF를 삭제·덮어쓰거나, 기존 원본 여러 페이지를 한꺼번에 교체하지 않음.

## 6. 다음 안전한 수락 검수 순서
1. **서브노트 새 원본** 2페이지 (신규 전용 키, 시험용 토픽): 첫 장 직접 연결/2장 연속 보기 확인.
2. **기존 원본 누락 보충**: 중복 없는 원본 키·실제 시작번호를 선택한 시험용 자료만 사용.
3. **보강(ADD) 앞/뒤**: 새 -ADD 키와 원본 순서 확인; 기존 원본 페이지번호 불변 검사.
4. **개정(R) 2~3페이지**: 첫 장 마지막 업로드, 본문/관계행, 원본 파일ID 보존 및 활성 개정만 표시 확인.
5. **기존 원본에서 파일 교체 2페이지**: 직접 덮어쓰기 없는 새 -R 개정본 생성, 기존 원본 유지 확인.
6. **Windows / Galaxy Tab / iPhone** 기기별 확대·축소·원본 이전/다음·주석·메뉴 동작.
7. 각 단계에서 발생한 문제는 **통합ID/출처유형/페이지키/자료 유형/사용 파일의 페이지 수/오류 메시지/저장 성공 여부**로 증적 수집 후 관련 기능만 수정.
- 실제 등록 검수는 원본과 충돌하지 않는 자료·토픽이 확보된 경우에만 진행. **실제 운영 데이터에 시험파일을 임의 생성하거나 추가하지 않음.**
