# 학습노트 콘텐츠 검수 최우선 정책 — 핵심요소 완전성 및 원문 보존 (2026-10-12)

## 1. 사용자가 확정한 최우선 요구
> **설명은 짧아도 길어도 무방하다. 토픽의 핵심 구성요소, 기술요소, 절차, 세부절차, 아키텍처 요소 등 중심 키워드와 핵심 단어가 누락되거나 삭제되어서는 안 된다.**

- 기술요소 설명의 글자 수 자체는 품질이나 수정 필요성을 판정하는 기준이 아니다.
- 해당 토픽의 **핵심 지식의 완전성(coverage), 기술적 정확성(accuracy), 원문 보존(preservation)**을 최우선으로 한다.
- 유려한 표현·일정한 길이·형식적 통일을 이유로 핵심 항목을 축약·삭제·누락·의미 변형하지 않는다.
- 하나의 짧은 설명이라도 해당 토픽에서 핵심 역할이 정확히 전달되고 다른 주요 요소를 빠뜨리지 않았다면 그대로 유지한다.
- 긴 설명이라도 필수 구성요소가 빠졌거나 내용이 틀렸다면 별도 검토 대상으로 분류한다.

## 2. 필수 보존·검수 범위
1. **핵심 기술요소·구성요소**: 고유 명칭, 기술명, 공식 약어·영문, 핵심 키워드, 구성요소의 필수 목록 및 상하위 관계.
2. **절차·세부절차**: 단계명, 하위 단계명, 실행 순서, 선행 조건·분기, 중요한 입력/처리/출력, 단계 간 연결.
3. **아키텍처·구성도**: 필수 컴포넌트와 계층, 인터페이스, 호출·통신·데이터·제어 흐름, 구성요소 간 관계와 경계.
4. **알고리즘·수식·기법**: 핵심 연산 원리, 주요 처리 단계, 적용 조건, 수식과 변수·기호의 정확한 의미.
5. **표준·프레임워크·프로토콜**: 공식적으로 정해진 구성영역·기능·흐름·필수 명칭, 역할과 적용 조건.

항목이 반복되는 것과 항목이 사라지는 것은 구별한다. 같은 기술요소를 여러 곳에서 설명하더라도 특정 필수 단계·구성요소를 '중복'으로 단정하여 삭제하지 않는다. 차이(예: 인증과 인가, 분산과 복제, 검증과 확인)가 학습상 핵심이면 반드시 구별한다.

## 3. 앞으로의 검수 순서(우선순위)
1. **완전성**: 해당 토픽에 필수적인 핵심 요소·단계·하위단계·기능·관계·키워드가 빠졌는가?
2. **정확성**: 명칭·기능·표준·수식·순서·대응 관계가 정확한가?
3. **의미 충실성**: 각각의 설명이 요소명을 올바르게 설명하고, 인접 요소와 역할 구분이 되는가?
4. **가독성**: 원문의 의미와 구조를 보존하면서 사용자가 빠르게 이해할 수 있는가?
5. **길이·표현**: 글자 수는 누락 탐색의 보조 신호로만 사용하고 단독 합격/불합격 근거로 사용하지 않는다.

## 4. 누락을 입증하는 두 가지 검증을 구별
- **기존 원문 대비 손실 검사:** 안전하게 참조할 수 있는 이전 체크포인트·백업·버전과 대조하여 필수 항목이 실제로 삭제/축약되었는지 확인. 단순한 표현 차이와 실제 의미 손실을 구분한다.
- **기술적으로 필요한 핵심항목의 원천적 누락 검사:** 현재 토픽 I, 개념 J, 키워드 K, 등장배경 W, 특징 X, 구성요소 Y, 필요성 Z 및 인접 토픽을 교차검토하고, 필요한 경우 공식 기술자료와 대조한다. 현재 기록에 없다는 이유만으로 임의 생성하거나, 다른 필드에 있다는 이유만으로 기술요소에서 자동 삭제하지 않는다.
- 키워드(K)는 누락 탐색의 유력한 단서지만 완전한 공식 목록이나 단일 정답 원천으로 가정하지 않는다.
- 절차형 도식은 마지막 괄호의 설명만 따로 잘라 검사하지 않는다. 전체 단계·화살표·순서·중첩괄호를 포함하여 원문 구조를 검토한다.

## 5. 신규 판정 기준
- **유지 가능:** 기존 필수 항목과 의미가 충족됨; 원문 유지.
- **핵심 누락 의심:** 공식 기준·토픽 범위·이전 원본과 대조해 보완 필요성을 검증할 후보.
- **기술적 정확성 의심:** 기능/조건/수식/정의/단계 순서 등 정확성 추가 확인 필요.
- **표·도식·절차 형식 보존:** 핵심 정보가 짧은 표기나 전체 흐름 안에 포함돼 있어 개별 괄호 설명만으로 판단하면 안 됨.
- **기존 대비 손실 확인:** 신뢰 가능한 이전 버전과 정확한 차이가 확인된 경우에만 삭제·누락으로 확정하되 복구·수정은 별도 사용자 승인 전 금지.

판정대장은 **통합ID + 토픽명 + 요소명/세부단계 + 판정 + 검증 근거 + 기존 대비 비교 여부**를 명시한다. '누락 의심'은 '오류 확정'이나 '수정 승인'과 구별한다.

## 6. 기존 Phase 7~13 수치의 정확한 해석
- **10~15자 1,779건**과 **현재 미검수 1,400건**은 과거에 길이를 기준으로 선별한 후보 집단의 상태를 나타낼 뿐, 전체 기술요소·구성도·세부절차의 완전성 검수 범위를 대표하지 않는다.
- **379/1,779 = 21.3%**는 이 *길이 구간의 1차 개별 문맥검수 진행률*만 의미한다. **전체 22,424개 최상위 항목의 품질검수 완료율이 아니다.**
- Phase 13에서 새로 확인한 50건은 Phase 8/10의 과거 표본과의 상세 중복검증을 마치지 못했으므로 379건에 임의 가산하지 않는다.
- 과거 체크포인트는 삭제하거나 새 기준으로 소급해 '오류'로 재판정하지 않는다. 다만 이후 작업에서는 **글자 수보다 핵심 지식 보존을 우선**하는 새 정책을 적용한다.
- 과거 1,400건을 계속 검토할 수 있지만, **긴 설명에서 필수 기술요소가 누락됐는지**도 별도의 누락 검수 대상으로 포함해야 한다. 정확한 전체 누락 건수는 검증 전까지 단정하지 않는다.

## 7. 변경·공개 제한
- 운영 Google Sheets 원문 K/W/X/Y/Z의 자동 입력·교정·삭제·재작성·대량치환은 별도 사용자 지시 없이 **금지**.
- 누락이 확인되어도 우선 **수정 제안 목록**에만 기록하고, 원문 변경은 승인 이후 범위를 특정해 진행.
- 메인뷰어 A안의 번호·줄바꿈·`gap: .52rem` 보존; PDF·검색·관리·인증·첨부자료 기능 불필요한 변경 금지.
- TTS/MP3 재합성·GCS·매니페스트·Cloud Run 변경 금지.
- 공개 GitHub에는 집계·최소한의 항목명·판정 근거만 기록하고 비공개 학습 원문 전체·대량 상세 인덱스·MP3를 올리지 않는다.
- 이 문서는 **검수 정책을 기록한 것**이며 검수·실기기 QA·누락 복구 완료를 뜻하지 않는다.
- Apps Script를 수정하지 않으므로 **저장 불필요 / 함수 실행 불필요 / 재배포 불필요**.

## 8. 후속 실행
1. 이 정책을 Phase 13 이후 모든 콘텐츠 검수의 최우선 기준으로 사용.
2. 기존 1,400건 후보를 다룰 때 각 토픽의 **완전한 요소 목록과 하위 절차·아키텍처 맥락**을 먼저 확인하고 그다음 설명의 정확성·충분성을 검토.
3. **길이에 무관한 필수항목 누락**을 별도의 검수 경로로 추가하고, 백업/참조자료·공식 정의와 교차확인.
4. 누락 의심·정확성 의심은 원문 변경 없이 통합ID별로 추적하고, 사용자 승인 시에만 운영 원문 수정.
