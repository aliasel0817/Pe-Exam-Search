# 학습노트 긴급 인터럽트 — 새 원본 다중 PDF 자동 분할 (2026-10-12)

## 목표 및 기준
- 사용자 확정: 신규 토픽/기존 토픽 수정에서 새 서브노트·교재 원본이 없을 때 **여러 페이지 PDF 파일 하나를 선택**하면 **브라우저에서 1페이지 PDF로 분할**, 각 페이지를 **새 페이지키:페이지번호**에 저장. 토픽에는 첫 페이지(`새키:1`)만 연결. 뷰어 원본 다음 페이지에서 `새키:2` 이후 탐색.
- 기존 페이지 파일·페이지키·원문·주석·원본 링크는 변경하지 않음. 기존 단일페이지 '누락/보강/개정/교체' UI 제한은 유지.

## 구현
- 변경 파일: `study-note/study-note.html` 1개, 테스트 `study-note/tests/test_reference_pdf_multipage.cjs`, GitHub Actions `.github/workflows/study-note-pdf-upload.yml`, 이 체크포인트.
- 프런트 후보 버전 `4.6.10-multipage-original-pdf-rc1`.
- 기존 내장 PDF-Lib 1.17.1 로더를 재활용해 **새 원본/새 문서에만** 클라이언트측 페이지분할. 기존 Apps Script `referencePdfRegistrationPlan`으로 새 키를 발급, `uploadReferencePdfPage`를 각 페이지에 순차 호출.
- 1페이지 출력 PDF 파일명은 기존 서버 규칙 `페이지키_0001.pdf`, `페이지키_0002.pdf` 등.
- 신규 원본 64MB 이하, 200페이지 이하, 분할 후 개별 파일 8MB 이하로 제한. 제한/암호화/손상/충돌 시 등록 준비에서 중단. 이 값은 초기 안전 상한으로, 실제 필요가 있으면 별도 검토하여 변경할 수 있음.
- 첫 페이지의 새 페이지키 등록 완료 이후 나머지는 같은 페이지키에 저장. 같은 원본의 원본페이지를 스크롤·앞/뒤로 탐색하는 기존 뷰어 로직 활용.
- 토픽 연결 필드에는 `새페이지키:1`만 추가. `새페이지키:2` 이후는 전체 PDF 페이지 파일목록에만 등록하고 해당 토픽의 직접 연결목록에 넣지 않음.
- 준비 중 저장 차단, 자료유형/관리모드 변경 중 오래된 비동기 결과 무효화, 기존 페이지와의 충돌 탐지, 업로드 후 기록 유지·재시도 지원.

## 실제 수락 테스트
1. 계정이 승인된 PC에서 신규/기존 토픽을 열고 `서브노트 PDF 페이지` 또는 `교재 PDF 페이지` → `새 PDF 자료 등록` → `새 원본/새 문서` 선택.
2. 2페이지 PDF 1개 선택 → `등록 준비 추가` 클릭 → 준비 확인: 새 페이지키의 1~2페이지, 토픽 연결 목록에는 첫 페이지 **1개만 표시**.
3. 저장 후 PDF 뷰어 첫 화면의 1페이지 표시 확인, **원본 다음 페이지**에서 2페이지 표시, 이전 페이지 1페이지 복귀 확인.
4. 토픽 신규/기존 수정 각각, 서브노트/교재 각각에 대해 확인.
5. 기존 등록 교재·서브노트 PDF 및 일반 PDF 업로드·교체·보강·개정 조작 이상 여부 확인.
6. 부분 실패 발생 시 이전 업로드가 완료된 항목은 재업로드하지 않고 **같은 관리창에서 저장 재시도**. 취소 시 이미 생성된 신규 페이지들이 Drive에 남을 수 있으므로 신중히 확인.
