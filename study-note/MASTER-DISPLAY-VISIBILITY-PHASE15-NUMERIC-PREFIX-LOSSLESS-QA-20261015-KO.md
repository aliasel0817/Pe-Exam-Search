## 2. 발견 결함: 숫자형 기술표준·주파수를 작성 번호로 오인
- 기존 `splitStudyItemsForDisplay`는 원문에 이미 작성된 `1.`, `1)`, `가.` 목록을 덧번호 매기지 않으려고 `\d{1,3}[\).]`를 사용. 그러나 바로 뒤 **숫자**가 오는 마침표도 번호 구분자로 판단해 X열 분리를 불필요하게 금지.

- 각 셀에는 명확한 최상위 ` · ` 구분 **4항목**이 있었으나, 이전에는 모두 원문 직접 한 줄로 표시. **원본 데이터 손실이 아닌 화면 구조 분리 누락**.

## 4. 구조 적용 범위: 전체 3,800토픽 X/Y read-only 대조
- 기존 정규식과 새 정규식의 분리 결과를 **모든 학습대상 3,800건 X/Y 문자열**에 대해 별도로 대조.
- X 구조적 목록: **이전 3,793/3,800셀 → 신규 3,798/3,800셀 (+5)**. 실제 변화 ID가 위 5개와 정확히 일치.
- 해당 5개 X셀: 각각 4요소로 분리, 원문 순서 그대로 **20개 독립 항목**. `items.join(' · ') === X원문` 정확 일치 **5/5**, 누락 0.
- Y 분리 결과 변화 **0셀**. 기존 최종 Y 목록 적용 **3,796/3,800셀** 유지(다중요소 목록 + 기존 단일 요소 목록 포함; 단순 splitter만으로는 단일 요소 목록 22건이 계산되지 않음).
- 신규 X 원문 직접 표시 **2셀**: `T4037` 공란, `T4038` 이미 작성된 하이픈 다중행. Y 원문 직접 표시 기존 **4셀**: `T3297`·`T4036`·`T4038` 기작성 번호/계층형, `T4037` 공란.

- Phase 12의 7,600셀·36,944원문 요소 무손실 전체 DOM 검사는 **지난 단계의 실적**. 이번 Phase 15에서 모든 7,600셀 DOM 검사를 다시 실행했다고 기록하지 않음. 변경 5셀 실제 원문 DOM 검수와 전수 splitter 전후 대조만 새 검증으로 구분.
