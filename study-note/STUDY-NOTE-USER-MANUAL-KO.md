## 2. 처음 실행 및 기기 설치

### 2.1 사이트 열기

1. 위 **운영 주소**를 브라우저에서 엽니다.
2. 학습 데이터가 없으면 **최초 데이터 받기**를 누릅니다.
3. 이후 상단 **MASTER 갱신**으로 최신 내용을 다시 내려받을 수 있습니다.
4. 상단 네트워크/동기화·보안 상태를 확인합니다. 일반 읽기·검색은 브라우저의 IndexedDB를 사용합니다.

### 2.2 기기별 홈 화면 등록

- **Windows PC:** Chrome/Edge에서 운영 주소를 연 뒤 브라우저의 **설치** 또는 **앱/바로가기 만들기** 메뉴를 사용합니다. 메뉴 이름은 브라우저 버전에 따라 다릅니다.
- **Galaxy Tab:** Chrome에서 운영 주소를 열고 메뉴의 **홈 화면에 추가/앱 설치**를 사용합니다.
- **iPhone:** Safari에서 운영 주소를 열고 **공유 → 홈 화면에 추가**를 사용합니다.

설치는 접근을 편리하게 하는 선택사항입니다. **앱을 설치해도 관리 쓰기 권한은 자동 부여되지 않습니다.**

### 2.3 오프라인 사용 범위

- **가능한 부분:** 이미 내려받은 토픽 텍스트 조회·검색 및 일부 기기 로컬 상태.
- **온라인이 필요한 부분:** MASTER 갱신, Google Sheets/Drive 쓰기와 동기화, 아직 받지 않은 PDF 열기, 온라인 문제목록 갱신, 신뢰기기 확인 등.
- PDF 파일이 로컬에 영구 보관된다고 가정하지 마세요. 필요하면 네트워크가 연결된 상태에서 열어 확인합니다.

## 3. 검색과 토픽 이동

### 3.1 검색어 입력

1. 좌측 **검색어**에 토픽명 또는 키워드를 입력합니다.
2. **세미콜론(;)**으로 여러 단어를 구분하면 OR 검색을 합니다. 예: 클라우드;가상화.
3. **검색대상**에서 토픽명·개념·키워드·암기법 중 검색할 열을 복수 선택할 수 있습니다.
4. **학습대상(Y/N/전체)**, **중요도(상/중/하)**, **도메인**, **대분류**로 범위를 좁힙니다.
5. 원상복귀는 **초기화**를 누릅니다.

### 3.2 목록 이동

- 결과 목록의 토픽을 선택하면 중앙에 학습 본문이 열립니다.
- 목록 하단에서 페이지번호를 입력하거나 **이전/다음**, **30·50·100개씩**을 선택할 수 있습니다.
- 본문 하단의 **이전/다음** 버튼은 토픽 이동입니다. PDF 원본 페이지 이동과 다릅니다.
- 좁은 화면에서는 왼쪽 위 **☰ 검색 및 목록**으로 목록을 엽니다.

## 4. 토픽 본문과 회상 학습

본문에는 통합ID·도메인·대분류·중요도·학습대상과 함께 **개념, 등장배경, 필요성, 특징, 기술요소/구성요소, 키워드, 암기법, 관련토픽**이 표시됩니다.

### 4.1 가독성 표시 규칙

- 등장배경·필요성·특징·기술요소/구성요소는 메인뷰어의 읽기 쉬운 번호·줄바꿈 형식으로 표시됩니다.
- 영문 기술요소는 가능한 범위에서 한글 뜻을 함께 보여줍니다.
- **표시용 가공은 원본 Google Sheets 문구의 삭제·축약·교체를 의미하지 않습니다.** 필수 구성요소·세부 절차·수식·순서를 임의 삭제하지 않습니다.
- 자료가 부정확하거나 누락이 의심되면 저장 원문을 바로 바꾸지 말고 관리자 검수 대상으로 남깁니다.

### 4.2 회상 학습

1. 토픽 상단 **◐ 회상 OFF**를 누르면 회상 모드로 전환됩니다.
2. 개념·키워드·암기법의 내용을 기억해 봅니다.
3. 해당 카드의 **보기** 버튼으로 정답 내용을 펼쳐 확인합니다.
4. 기억했다면 **✓ 기억함**, 다시 공부할 내용이면 **↻ 다시보기**를 누릅니다.
5. 토픽 이동 후에도 본인의 학습기록을 관리할 수 있습니다.

회상 모드는 **학습 화면의 표시 방식**이고, 실제 본문을 수정하는 기능이 아닙니다.

## 5. 즐겨찾기·학습기록·개인메모

### 5.1 기록 버튼

- **☆ 즐겨찾기:** 다시 찾을 토픽을 표시합니다.
- **✓ 기억함:** 해당 토픽을 암기한 것으로 기록합니다.
- **↻ 다시보기:** 복습이 필요한 토픽으로 기록합니다.
- 동일한 토픽을 같은 날 반복 누를 때 복습/미암기 횟수는 코드의 일별 중복방지 규칙을 따릅니다.

### 5.2 학습 대시보드

1. 상단 **▣ 학습**을 누릅니다.
2. **최근학습 / 오늘의 학습 / 미암기 복습 / 즐겨찾기** 탭에서 목록을 확인합니다.
3. 학습대상·학습함·암기·미암기·즐겨찾기·오늘 학습 수와 진도율을 확인합니다.
4. **↕ 학습정보 동기화**는 학습정보를 기기와 Google Sheets의 학습정보 영역에 맞추는 별도 쓰기 작업입니다.
5. **현재 토픽 초기화 / 전체 학습 초기화**는 기존 학습기록을 변경하므로 내용을 읽고 꼭 필요한 경우에만 사용합니다.

### 5.3 개인메모

토픽 하단 **개인메모**에 직접 메모를 입력한 후 **메모 저장**을 누릅니다. 개인메모는 관리 팝업의 공용 토픽 설명과 다릅니다. 다른 기기에서도 같은 메모가 보이는지 확인하려면 신뢰기기/학습정보 동기화 상태를 별도로 확인하세요.

## 6. 기출·모의 문제 검색

1. 토픽명 오른쪽 **⌕ 문제 검색**을 누릅니다.
2. 현재 토픽 이름을 검색어로 사용하여 결과를 보여줍니다.
3. 팝업 검색창에 다른 단어를 입력하면 다시 검색할 수 있습니다.
4. 검색 결과가 많으면 페이지네이션으로 이동합니다.
5. 문제 목록 자체를 새로 받으려면 **⟳ 문제목록 갱신**을 누릅니다.

원본 문제 목록은 GitHub의 별도 문제파일에 기반하므로, **MASTER 갱신**과 **문제목록 갱신**은 서로 다른 동작입니다.

## 7. 토픽 관리: 신규·수정·학습 제외

> **주의:** 관리 기능은 Google Sheets 원문을 변경합니다. 승인된 신뢰기기에서만 사용하고, 입력 전 반드시 현재 토픽의 통합ID를 확인하세요.

### 7.1 현재 토픽 수정

1. 수정할 토픽을 선택합니다.
2. 상단 **✎ 관리** 또는 본문 오른쪽 **✎ 현재 토픽 관리**를 누릅니다.
3. 팝업의 **현재 토픽 수정**이 선택되어 있는지 확인합니다.
4. 통합ID와 토픽명을 다시 확인합니다.
5. 변경할 항목만 수정합니다.
6. 필요한 경우 교재·서브노트 PDF 페이지 연결이나 첨부자료를 추가합니다.
7. **저장** 후 성공 안내와 토픽 본문을 확인합니다.

### 7.2 새 토픽 등록

1. **관리 → ＋ 새 토픽**을 선택합니다.
2. 대분류, 중요도, 학습대상, 토픽명 등을 지정합니다.
3. 개념·등장배경·필요성·특징·기술요소/구성요소·키워드·암기법·관련토픽을 입력합니다.
4. PDF가 없으면 **PDF 페이지 연결 없이도** 토픽 저장이 가능합니다.
5. 필요한 경우 첨부자료 또는 새 원본 PDF를 추가합니다.
6. **저장**하면 서버가 최종 통합ID를 발급하므로, 저장 완료 메시지에서 ID를 확인합니다.

**기술사 학습 콘텐츠 원칙:** 짧고 예쁜 설명을 만들기 위해 필수 기술요소명·하위 절차·구성요소·아키텍처 관계·수식을 삭제하지 않습니다. 처음부터 확인된 원본을 그대로 보존하는 것이 우선입니다.

### 7.3 대분류·학습대상 관리

- **＋ 대분류 추가**는 신규 대분류가 필요할 때에만 사용합니다. 서버가 최종 코드의 중복을 확인합니다.
- **학습대상 N 처리**는 학습 제외 기능입니다. 원문 행 삭제와 다릅니다.
- 상태·학습제외사유 등을 변경하면 기존 검색·학습대상 필터에 영향을 줄 수 있습니다.

### 7.4 토픽 첨부자료 추가

- 관리 팝업 **첨부자료 → 이미지 추가 / PDF 추가**는 토픽에 연결되는 별도 파일 첨부입니다.
- 이 경로는 **교재/서브노트 원본 PDF 페이지키 자동 분할과 다른 기능**입니다.
- 원본 연속페이지 이동이 필요한 교재는 첨부 PDF 대신 아래 **원본 PDF 등록** 절차를 사용하세요.

## 8. 첨부 PDF와 원본 교재·서브노트의 차이

| 구분 | 원본 학습자료 | 첨부자료 PDF |
|---|---|---|
| 메인뷰어 위치 | **원본 학습자료 → 서브노트 보기 / 교재 보기** | **첨부자료 → PDF 보기** |
| 데이터 구조 | **출처유형 + 페이지키 + 실제 페이지번호** | 토픽별 첨부 파일 |
| 다중 페이지 등록 | [운영 반영] 브라우저가 페이지별 PDF로 분할 | 일반 첨부 파일 방식, 별도 파일 관리 |
| 이동 | **등록 이전/다음** 및 **원본 앞/뒤 1페이지** | 첨부 PDF 뷰어의 페이지/파일 탐색 |
| 추천 사용 | 학습 토픽과 교재/서브노트 연결, 연속 페이지 공부 | 추가 참고 PDF/개인 자료 |

### 8.1 페이지키·페이지번호·토픽 연결

- **페이지키:** 어느 원본 문서에 속한 페이지인지 나타내는 식별자. 예: SW-2.
- **페이지번호:** 해당 문서 안에서 사용하는 실제 페이지번호. 예: 613.
- **페이지토큰:** 페이지키와 페이지번호를 합친 값. 예: SW-2:613.
- **토픽 연결:** 토픽이 처음 열어 줄 페이지토큰 목록.
- **원본 연속 이동:** 토픽에 연결하지 않은 나머지 페이지까지 같은 원본/관계의 순서로 탐색하는 기능.

예를 들어 **새 교재 3페이지 PDF**를 업로드하면 가상의 새 페이지키 SW-4가 발급되어 SW-4:1 / SW-4:2 / SW-4:3이 저장되지만, 토픽에는 **SW-4:1만** 직접 연결합니다. **SW-4는 예시이며 실제 페이지키는 서버 계획에 따라 다릅니다.**

## 9. 다중 페이지 원본 PDF 등록: 공통 절차 — 운영 반영

**다중 페이지 기능은 운영 코드에 반영됐습니다. 최초 등록 전에 앱 버전이 4.6.11인지 확인하고, 원본 자료를 보호하려면 2~3페이지 시험용 PDF부터 검증하세요. 실제 Drive/시트 등록 QA는 아직 미완료입니다.**

### 9.1 공통 사용 순서

1. 인터넷이 연결된 신뢰기기에서 대상 토픽을 열고 **관리 → 현재 토픽 수정** 또는 **＋ 새 토픽**을 선택합니다.
2. **서브노트 PDF 페이지** 또는 **교재 PDF 페이지** 영역의 **새 PDF 자료 등록**을 펼칩니다.
3. **자료 유형**에서 작업 목적에 맞는 항목을 선택합니다.
4. **기준 페이지키**를 선택하고, 자료 유형에 따라 **기준/실제 페이지번호**, **앞/뒤**, **새 페이지키 직접 지정(선택)**을 설정합니다.
5. **PDF 파일**에서 여러 페이지로 된 PDF 1개를 선택합니다.
6. **등록 준비 추가**를 누릅니다. 브라우저가 **1페이지 PDF**로 분할하고 페이지 수·페이지키 범위·첫 페이지 연결 내용을 보여줍니다.
7. 등록 준비가 완료됐는지 확인한 후 **토픽 저장**을 누릅니다.
8. 저장 시 준비한 페이지들이 기존 서버 API로 순서대로 업로드됩니다. 성공 안내의 신규 페이지 수를 확인합니다.
9. 관리 팝업을 닫고 **원본 학습자료 → 교재 보기 / 서브노트 보기**에서 첫 페이지와 다음 페이지를 검증합니다.

### 9.2 준비만 한 상태와 실제 저장의 차이

- **등록 준비 추가:** 분할·페이지키 계획을 브라우저에서 준비하는 단계입니다. 이때 PDF 페이지 본문이 서버에 올라갔다고 단정하면 안 됩니다.
- **토픽 저장:** 실제 페이지별 업로드와 토픽 연결을 수행합니다.
- 업로드 진행 중 창을 닫거나 페이지를 새로고침하지 마세요. 페이지별 요청은 하나의 통합 트랜잭션이 아닙니다.
- 중간 실패 후 일부 페이지가 저장됐을 수 있습니다. **동일한 관리창에서 원인을 확인하고 저장을 다시 시도**합니다. 재시도 전에 창을 닫으면 준비 파일이 사라질 수 있습니다.

### 9.3 업로드 안전 제한

- 입력 파일 최대 **64MB**.
- 한 파일 최대 **200페이지**.
- 분할된 개별 1페이지 PDF는 각각 **8MB 이하**.
- 암호화·손상된 파일이나 페이지키 충돌 파일은 등록 준비가 실패할 수 있습니다.
- 특히 모바일 브라우저는 큰 PDF 분할에서 메모리가 부족할 수 있으므로 처음엔 2~3페이지 소규모 PDF로 검증하세요.
- 기존 페이지 파일을 덮어쓰지 않는 것을 기본 원칙으로 합니다.

## 10. 새 원본·누락·보강·개정·교체 사용법 — 운영 반영

### 10.1 새 원본/새 문서 — **기존에 교재가 없는 T4036 사례**

사용 시점: 새로운 토픽을 등록하거나 기존 토픽에 처음으로 교재/서브노트를 연결할 때.

**예시: T4036에 2페이지 교재 PDF 추가**

1. **T4036 → 관리 → 현재 토픽 수정**을 엽니다.
2. **교재 PDF 페이지 → 새 PDF 자료 등록**을 펼칩니다.
3. 자료 유형을 **새 원본/새 문서**로 선택합니다.
4. 기준 페이지키는 새 폴더를 생성할 때 참고할 기존 교재 저장 위치입니다. 해당 도메인의 적절한 키를 선택합니다.
5. **2페이지 PDF**를 선택하고 **등록 준비 추가**를 누릅니다.
6. 안내에 새 원본의 **1~2페이지 분할 준비**, **첫 페이지만 토픽 연결**이 표시되는지 확인합니다.
7. **저장**을 누르고 성공을 확인합니다.
8. 토픽의 **교재 보기**로 열어 첫 장이 보이고 **원본 뒤 1페이지 →**로 두 번째 장, **← 원본 앞 1페이지**로 첫 장이 나오는지 확인합니다.

서브노트도 **서브노트 PDF 페이지** 영역에서 같은 절차를 사용합니다. 새 토픽을 등록하는 화면에서 PDF를 함께 준비한 경우 최종 통합ID는 저장 시 서버가 부여합니다.

### 10.2 기존 원본의 누락 페이지 보충

사용 시점: 기존 교재 키가 있고 실제 페이지번호 613부터 두 장이 빠졌을 때.

1. 자료 유형 **기존 원본의 누락 페이지**를 선택합니다.
2. **기준 페이지키 SW-2** 등 실제 원본을 선택합니다.
3. **실제 시작 페이지번호 613**을 입력합니다.
4. 2페이지 PDF를 선택하고 등록 준비를 실행합니다.
5. **SW-2:613 / SW-2:614**처럼 기존 원본 키와 실제 페이지번호를 사용합니다.
6. **첫 페이지 SW-2:613만 토픽에 직접 연결**하고 나머지는 원본 연속 이동으로 봅니다.

**주의:** 614가 이미 존재한다면 해당 페이지를 새 파일로 덮어쓰지 않고 **충돌로 등록을 중단**하는 것이 정상입니다. 실제 누락이 아닌 경우에는 보강 또는 개정 절차를 선택하세요.

### 10.3 보강 페이지 — 기존 원본의 앞 또는 뒤에 새 자료 삽입

사용 시점: SW-2:613 바로 뒤에 새로운 설명 PDF 3장이 필요한 경우.

1. **자료 유형 → 보강 페이지**.
2. **기준 페이지키 → SW-2**, **보강 기준 원본 페이지번호 → 613**.
3. **보강 삽입 위치 → 기준 페이지 뒤**(또는 앞).
4. 3페이지 PDF 선택 → **등록 준비 추가**.
5. 신규 보강키가 예를 들어 **SW-2-ADD5:1~3**처럼 발급됩니다.
6. **보강 첫 장만 토픽에 연결**합니다.
7. 저장 후 해당 토픽에서 원본 페이지 앞/뒤 이동으로 보강 1·2·3장을 연속 확인합니다.

보강은 **기존 SW-2:614의 페이지번호를 617로 밀거나 변경하는 기능이 아닙니다.** 기존 페이지번호는 유지하고 화면상의 논리 탐색 순서에 새 보강 페이지를 추가합니다.

### 10.4 개정 페이지 — 기존 한 페이지의 새로운 버전 + 여러 추가 장

사용 시점: SW-2:613의 설명이 개정되어 3페이지짜리 새 판본을 사용하고 싶은 경우.

1. **자료 유형 → 개정 페이지**.
2. **기준 페이지키 SW-2**, **개정 대상 원본 페이지번호 613**을 선택합니다.
3. 3페이지 PDF 선택 → **등록 준비 추가**.
4. 예를 들어 **SW-2-R4:613 / :614 / :615** 같은 별도 개정키가 생성됩니다.
5. 저장하면 개정본 첫 장이 기준 613의 새 버전으로 표시되고, 나머지 2장이 그 뒤에 이어집니다.
6. **기존 SW-2:613 원본 PDF는 삭제하지 않습니다.**
7. 과거 다른 -R 버전의 추가 장이 최신 개정 흐름에 섞이지 않도록 논리 탐색을 분리합니다.

다중 페이지 개정본은 안전을 위해 **추가 페이지부터 업로드하고 첫 장을 마지막에 등록**하도록 설계했습니다. 중간 실패 시 미완성 개정본이 갑자기 최신 화면에 나타나는 위험을 낮추기 위함입니다.

**범위:** 현재 개정은 **기존 원본의 한 페이지를 기준**으로 합니다. 그 다음 기존 원본 페이지들을 임의로 삭제하거나 여러 원본 페이지 구간 전체와 1:1로 대체하지 않습니다.

### 10.5 기존 페이지 행에서 파일 직접 교체

현재 토픽의 페이지 목록에는 **기존 PDF 파일 교체** 입력란이 있습니다.

- **1페이지 PDF를 선택:** 기존 페이지토큰을 유지하는 기존의 직접 교체 기능입니다. 실제 기존 파일에 영향을 줄 수 있으므로 파일 내용과 페이지가 일치하는지 확인합니다.
- **2페이지 이상 PDF를 선택:** 기존 원본 페이지에서는 **원본 파일을 덮어쓰지 않고 별도 -R 개정 페이지키**를 생성합니다. 새 개정본이 완성되어야 기존 원본의 최신 표시를 바꿉니다.
- **이미 보강/개정된 페이지 행의 2페이지 이상 직접 교체:** 원본·판본 혼동을 막기 위해 제한합니다. 대신 **새 PDF 자료 등록 → 보강/개정**을 이용합니다.
- 한 번에 여러 기존 원본 페이지를 일괄 교체하는 기능은 없습니다. 어느 원본 범위를 개정할지는 사용자가 명확히 결정해야 합니다.

### 10.6 페이지를 수동 추가한 뒤 파일을 선택하는 경우

**페이지키 선택 → 페이지번호 입력 → 페이지 추가**로 목록을 만든 다음, 해당 행에 누락 PDF 파일을 선택할 수 있습니다. [운영 반영] 2페이지 이상 파일을 넣으면 **선택한 시작 페이지번호부터 연속 등록**할 수 있습니다. 중복·충돌이 있다면 새 원본·보강·개정 중 맞는 유형을 선택하세요.

## 11. PDF 뷰어: 페이지 이동·확대·주석

### 11.1 교재·서브노트 원본 열기

1. 토픽 본문 **원본 학습자료**에서 **교재 보기** 또는 **서브노트 보기**를 누릅니다.
2. 처음에는 토픽에 연결된 **첫 페이지**가 표시됩니다.
3. 뷰어 상단의 두 종류의 이동 버튼을 구분하세요.

| 버튼 | 용도 |
|---|---|
| **← 등록 이전 / 등록 다음 →** | 해당 **토픽에 직접 연결된 페이지 목록** 사이에서 이동 |
| **← 원본 앞 1페이지 / 원본 뒤 1페이지 →** | **원본의 실제/논리 연속 페이지**를 한 장씩 이동 |
| **상단 접기 ▲** | 상세 상단바를 접고 작은 앞/뒤 버튼을 표시 |
| **Drive에서 열기 ↗** | 현재 페이지를 Google Drive에서 직접 확인 |

**핵심:** 새 PDF 3장을 등록하고 토픽에 첫 장만 연결했다면 **등록 다음**은 없을 수 있습니다. 나머지 2장은 반드시 **원본 뒤 1페이지**를 눌러 확인하세요.

### 11.2 이미지·PDF 첨부 뷰어

**첨부자료 → 이미지 보기 / PDF 보기**는 원본 교재와 별개입니다. 첨부 PDF는 자체 페이지 이동, 확대·축소, 맞춤, 기기에서 가능한 경우 손가락 확대를 사용합니다.

### 11.3 주석 사용

뷰어의 주석 도구에는 **이동, 선택, 펜, 형광펜, 지우개, 직선, 화살표, 사각, 원, 텍스트, 메모**가 있습니다. 색상·굵기·투명도, 실행취소/다시실행, 복제, 선택삭제, 앞/뒤 정렬, 표시, 관리, 전체삭제를 지원하는 화면이 있습니다.

1. **✋ 이동** 모드에서 PDF를 이동·스크롤합니다.
2. 표시할 항목에 맞는 도구를 선택하고 그립니다.
3. 주석 **저장 상태**와 페이지/문서 전환 후 유지 여부를 확인합니다.
4. **← 이전 주석 / 다음 주석 →**, **북마크**, **중요**는 학습 주석 이동·분류에 사용합니다.
5. **전체삭제**는 복구가 어려울 수 있으므로 의도한 문서/페이지인지 확인한 뒤 실행합니다.

주석의 기기간 동기화 및 모든 터치 제스처는 기기별 실사용 QA를 완료하지 않았으므로, 중요한 주석은 최초 사용 시 작은 샘플로 저장·복구를 확인하세요.

## 12. 신뢰기기 인증·동기화·설정

### 12.1 관리가 잠겨 있을 때

- 일반 토픽 조회는 로그인·기기 승인 상태와 별개로 가능할 수 있지만, 토픽 변경·첨부 업로드·학습정보 쓰기는 **ACTIVE 신뢰기기**가 필요합니다.
- **⚙ 설정 → 🔐 인증 · 신뢰기기 관리**를 엽니다.
- 새 기기에는 기기 이름을 적고 **Google로 이 기기 등록**을 누른 후, 기존 신뢰기기에서 승인합니다.
- **승인 상태 확인**으로 결과를 갱신합니다.
- **Google + 관리 PIN으로 긴급 복구**는 일반 가입용이 아니라 초기 등록·긴급 복구용입니다. PIN을 외부에 공유하거나 매번 입력하지 마세요.
- **등록 기기**에서 오래된 기기를 차단할 수 있습니다. 차단은 쓰기 권한을 무효화합니다.

### 12.2 MASTER와 학습정보는 다른 동기화

| 메뉴 | 동기화 대상 | 사용 시점 |
|---|---|---|
| **MASTER 갱신** | 운영 토픽 콘텐츠·메타데이터 다운로드 | 새 토픽·개념·기술요소 등 원문 변경 후 |
| **학습정보 동기화** | 사용자 개인 학습상태·즐겨찾기·메모 등 학습정보 영역 | 여러 기기에서 학습한 기록을 맞출 때 |
| **문제목록 갱신** | 문제검색용 목록 | 기출·모의 문제 목록이 바뀌었을 때 |

### 12.3 설정에서 확인할 것

- 기본 공용 Apps Script Web App URL은 앱에 내장되어 있습니다. **문제가 없으면 임의로 변경하지 않습니다.**

- **로컬 토픽 / 마지막 MASTER 갱신 / 앱 버전**을 확인합니다.

- 원본 PDF와 추가자료 PDF를 같은 기능으로 혼동하지 않습니다.
- 실패 후 관리창을 이미 닫았다면 이전 배치 성공/실패 정보를 관리자에게 전달하고 안전한 복구를 먼저 검토합니다.

## 22. 보강·개정 PDF 저장 후 서버 관계 확인

### 22.1 적용 대상과 목적

**4.6.14부터** 교재·서브노트에서 **2페이지 이상인 보강·개정 PDF**를 등록하면 기존처럼 페이지별 파일 업로드를 수행한 다음, 토픽 원문을 저장하기 **직전에 실제 서버 PDF 관계 목록을 다시 조회**합니다.

관리 화면에는 **“보강·개정 PDF 서버 관계를 다시 확인하는 중...”**이 표시될 수 있습니다. 서버가 다음 정보를 정상적으로 반환해야 다음 저장 단계로 진행합니다.

| 검증 항목 | 정상 조건 |
| --- | --- |
| Drive PDF 파일 | 분할 업로드한 각각의 페이지토큰과 파일ID 일치 |
| 보강 페이지 | 자료유형 '보강', 기준 원본키, 기준 원본 페이지토큰, 삽입 앞·뒤 위치 일치 |
| 개정 첫 장 | 자료유형 '개정', 기준 원본키와 대체대상 페이지토큰 일치 |
| 개정 계속 페이지 | 자료유형 '보강', **동일한 새 -R 키**, 같은 기준 원본과 '뒤' 위치로 등록 |
| 페이지 활성여부 | 검증 대상 신규 페이지가 비활성 상태가 아님 |
| 관계 누락 | 신규 분할 페이지 전체가 서버 조회 목록에 존재 |

기존의 **새 원본·누락 원본** 등록 동작은 변경하지 않았습니다. 단일 1페이지 PDF 등록도 이전 절차 그대로입니다.

### 22.2 실제 사용 순서

1. 대상 토픽을 선택하고 **관리 → 현재 토픽 수정 또는 새 토픽**을 엽니다.
2. **교재/서브노트 PDF 페이지 → 새 PDF 자료 등록**에서 **보강 또는 개정**을 선택합니다.
3. 기준 원본 페이지키와 페이지번호·보강 앞뒤 위치를 확인한 후 다중 페이지 PDF를 선택하고 **등록 준비 추가**를 누릅니다.
4. 분할 페이지 수와 별도 페이지키 `-ADD#` 또는 `-R#`를 확인하고 **저장**합니다.
5. PDF 페이지 업로드 이후 **서버 관계 재조회/검증**이 통과하면 토픽 저장과 연결 처리가 이어집니다.
6. PDF 뷰어에서 **원본 앞/뒤 1페이지**로 개정/보강 페이지 전체의 순서를 확인합니다.

### 22.3 검증 실패 또는 통신 오류 시

- **“서버 관계 검증 실패”** 메시지: 페이지 파일이 저장되었어도 자료유형·앵커·대체대상·파일ID 중 하나가 일치하지 않는 경우입니다. **저장 성공으로 간주하지 않습니다.**
- **“서버 관계 재조회에 실패”** 메시지: 등록 직후 통신 문제로 서버의 실제 관계정보를 읽지 못한 경우입니다. **파일이 이미 일부 또는 전부 업로드됐을 수 있습니다.**
- **공통 조치:** 관리창을 닫거나 페이지를 새로고침하거나 새로운 페이지키로 재등록하지 않습니다. **현재 관리창에서 상태를 확인하고 같은 저장 작업을 재시도**합니다. 오류가 계속된다면 통합ID, 출처유형, 원본키, 새 키, 자료유형과 정확한 오류 문구를 기록해 원인 검수를 요청합니다.
- 기존 PDF의 삭제·덮어쓰기·대량 시트 수정은 실행하지 않습니다.

### 22.4 확인 범위와 알려진 제한

이 재검증은 **페이지별 관계 데이터**를 확인하며, `PDF페이지키` 관리표의 자료유형이 ‘보강’ 또는 ‘개정’으로 표시되는 문제까지 자동으로 수정하지 않습니다. 특히 다중 개정의 계속 페이지가 먼저 새 -R 키를 생성하기 때문에 서버 관리표의 자료유형이 ‘보강’으로 남을 가능성은 **실제 첫 개정 등록 이후 별도 확인**해야 합니다.

**자동 회귀검사에서는** 정상 관계, 누락·오류 데이터, 서버 통신 실패·동일 창 재시도, 토픽 저장 전 검증 순서가 통과했습니다. **실제 Apps Script에 신규 보강·개정 PDF를 쓰는 종단간 시험은 여전히 미실시**입니다.

## 23. 다중 PDF 페이지 식별정보·누락 검증

### 23.1 보강·개정 저장 시 추가 확인

4.6.15에서는 기존 서버 관계 재조회 검증을 보완하여 **분할 PDF 대기 페이지 수와 순서**, **서버 페이지키·실제 페이지번호**, **개정 판본**을 함께 확인합니다. 자료유형과 Drive 파일ID 확인은 종전과 같이 수행하며 기존 원본 PDF를 변경하지 않습니다.

| 상황 | 프로그램 동작 |
|---|---|
| 분할 대기 페이지의 일부가 빠졌거나 순서가 중복됨 | 토픽 저장 차단 및 관리창에서 상태 확인 안내 |
| 업로드 계획과 서버의 페이지키·페이지번호가 다름 | 서버 관계 검증 실패; 토픽 저장 중단 |
| 지정한 개정 판본과 서버 판본이 다름 | 서버 관계 검증 실패; 토픽 저장 중단 |
| 다중 PDF의 계속 페이지가 토픽에 직접 연결됨 | 잘못된 직접 연결을 차단 |

### 23.2 현재 검증 범위와 유의사항

- 이 추가 검사는 **보강·개정의 다중 페이지 배치**에 적용됩니다. 기존 단일 페이지 직접 교체, 일반 원본 등록 흐름은 종전 기능을 유지합니다.
- 신규 원본·누락 원본 전체 페이지의 서버 관계 재조회 범위는 별도 후속 검토 대상입니다.
- 서버가 논리순서 값을 재계산할 수 있어 정확한 숫자 동일성은 검증하지 않습니다. 논리순서 정합성과 이전 개정본의 혼입은 화면 논리 탐색 및 회귀시험과 함께 판단합니다.
- `PDF페이지키` 관리표의 -R 자료유형 표시는 자동 보정하지 않았습니다. 실제 개정 등록 후 읽기 전용 확인이 필요합니다.
- 자동검사 통과와 운영 실기기 검증은 별개의 단계입니다. 시험용 신규 PDF를 이용한 실사용 QA 이전에는 보강·개정 실사용 완료로 표시하지 않습니다.
