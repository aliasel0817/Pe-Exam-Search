## 1. 목표 및 범위

Stage 1~5에서 조사·설계·개발한 다중 기기 학습계획 동기화 후보 기능을 **사용자가 이해하고 안전하게 사용할 수 있도록 UI·문구·상태 표시·오류 복구 UX를 개선**한다.

대상: 오늘의 학습계획/100일 5회독, 신규 토픽 편입·신규 계획, 회독별 완료/다시보기, 최초 통합 마법사, 일반 학습정보 동기화 버튼, 진도/전체 JSON 백업·복원 안내.

**개발·설계 80%, 핵심 검수·운영 20%.** Stage 6은 격리·합성 환경에서 구현한다. 운영 Google Sheets, LIVE MASTER, Apps Script, 실제 사용자 진도, GitHub main/Pages **변경·배포 금지**.

## 3. 세부 수행사항

### 3-1. 동기화 상태를 3개 영역별로 정확히 표시

기존 \`학습정보 동기화\` 버튼을 보존한다. 영역별 상태를 \`일반 학습정보 / 학습계획·일정 / 회독별 진도\`로 구분하여 개별 완료·부분 성공·실패·미지원·인증 필요·오프라인 상태를 표시한다.

서버의 확정 ACK/버전·커서 확인 전에는 '동기화 완료' 표시 금지. 동일한 button click 후 일반 학습정보만 성공했으면 계획·진도도 성공한 것처럼 보고하지 않는다. 최근 성공 시각, 미전송 N건, 충돌 N건, 원격 버전/로컬 버전의 필요한 정보를 간결하게 표기한다. 전송 실패하더라도 로컬 학습은 계속 가능해야 한다.

### 3-2. 오늘의 학습계획 표시와 기존 기능 보존

기존 시작일/오늘 N일차/회독·날짜/계획 수/완료·다시보기·미완료 표시를 유지한다. 일차는 **실제 시작일 기준(Asia/Seoul)** 으로 계산하고 날짜 선택과 별도임을 혼동하지 않게 한다.

작은 화면에서 통계를 1~2행으로 배치하고 기존 이전/다음/목록/학습/페이지 이동·그룹 필터·검색/페이지당 보기 등을 보존한다. 기존 수식·일정·MASTER 관련 정보 삭제·축약·변경 금지.

### 3-3. 최초 통합 7단계 마법사 UI 완성

Stage 5의 최초 통합 상태 \`BACKUP_PREPARED→BACKED_UP→REVIEW_REQUIRED→UPLOADING→SYNC_READY/CONFLICT_HELD/PENDING_RETRY\` 를 직관적으로 표시한다.

1) 전체 백업 다운로드 및 계획/진도/미전송 건수, 2) **실제 다운로드 파일 다시 선택·SHA 검증**, 3) 서버 버전·일정·진도 조회, 4) 동일·안전한 추가·충돌 분류 및 비교 예시, 5) 안전 항목 선택 + 사용자 승인, 6) 진행·업로드/부분 성공·중단 재개, 7) 서버 ACK·해시·seq 최종 확인.

계획 충돌은 원래 일정과 서버 일정을 각각 표시한다. 같은 \`planId|date|topicId\`의 done/miss/todo 상충은 양쪽 원본을 보여주고 **자동 최신값 선택 금지**. 충돌 보류 상태와 기록 원본 보존을 명확히 표시한다. 미리보기 전 업로드 버튼 비활성, 진행 중 중복 클릭 방지, 취소는 **서버 전송 이전**에만 허용. 브라우저 종료 후 \`preSyncSnapshots\`로 재개 가능하게 한다.

### 3-4. 학습계획 추가·진도 백업/복원 안내 정합성

기존 \`학습계획 추가 · 진도 백업/복원 사용 안내\`를 현재 실상에 맞춰 수정한다.

- '기기에만 저장'은 기능 OFF/인증 미지원/첫 통합 전인 경우 **로컬 전용**, 검증된 동기화 준비 이후에는 **신뢰기기 간 공유·오프라인 미전송**으로 구분한다. 배포 전에는 '모든 기기 자동 공유 중' 같은 허위 안내 금지.
- 신규 토픽 5회 자동 편입 / 새 학습계획 생성 / CSV·JSON 파일 등록 / 진도 백업 / 진도 복원 / 전체 최초 통합 안내를 명확히 구분한다.
- 섹션 ①~⑥ 및 진도 백업→복원 안내의 참조 번호를 실제 화면과 일치시킨다. 특히 '②에서 받은 진도 백업'처럼 잘못된 구형 번호를 수정.
- **JSON 백업은 동기화와 별도 안전망**임을 안내. 백업 파일은 전체 계획·진도·전송 대기 작업을 포함하지만 세션 토큰/비밀키는 포함되지 않음.
- 로컬과 서버 일정/진도가 충돌하면 임의 복구/덮어쓰기 유도 금지. 실행 가능한 오류·재시도·재백업 안내를 제공한다.

### 3-5. UI/접근성/디바이스 대응

PC 1366px, 태블릿 768px, 모바일 390px 등 대표 뷰포트의 합성 브라우저 시험. 긴 계획명/한글·영문/대용량 표시에서 스크롤·버튼 중첩·줄바꿈·대화상자 포커스 문제 확인. 레이블, tabindex, aria-live, 터치 목표 크기 및 키보드 동작 점검.

가능하면 \`study-note/study-note.html\` 보호 범위에 손대지 않고 기존 \`study-planner.js\` 또는 전용 sidecar에서 화면만 변경한다. 기존 MuPDF/AGPL 검사는 HTML 전체 바이트 보호를 가정하므로 HTML 수정 필요 시 영향과 테스트 변경을 별도로 근거화한다. 기존 PDF·이미지·첨부·필기·보안 코드를 건드리지 않는다.

### 3-6. 오류 처리·도움말

상태별 도움말을 제공한다: \`오프라인\`, \`신뢰기기 미승인\`, \`서버 API 미지원\`, \`백업 파일 해시 불일치\`, \`진도 충돌\`, \`계획 버전 충돌\`, \`부분 저장 후 ACK 유실\`, \`재시도 대기\`, \`브라우저 저장 공간 부족\`.

진도 미학습(이벤트 없음)과 명시적 초기화(\`todo\`) 구분. 회독별 진도를 기존 일반 학습정보 \`암기/미암기\`와 혼동하지 않게 안내한다.
