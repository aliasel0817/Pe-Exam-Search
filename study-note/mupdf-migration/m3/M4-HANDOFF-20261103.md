## 0. 최우선 지시
M0~M3에서 구현한 코드와 검사 결과를 재사용하여 M4 개발을 실제 수행한다. 동일한 기준선 조사를 불필요하게 반복하지 않되, 최신 GitHub main, 미병합 PR, 원격 PC 미커밋 작업, 실제 운영 소스, 승인받은 API/배포 버전을 착수 시 확인한다. **운영 main·Apps Script·GitHub Pages 절대 변경하거나 배포하지 않는다.** AGPL 법적 공개 범위가 확정되지 않았으므로 MuPDF JS/WASM을 공개 사이트, PR 바이너리, 외부 프리뷰에 배포하지 않는다. M4 기능은 독립 브랜치와 loopback 127.0.0.1 테스트 환경에서만 검증한다.

## 4. M4 purpose
**서브노트 보기와 교재 보기**가 내부 공통 MuPDF.js 렌더러를 사용할 수 있도록 신규 UI 연결 코드를 실제 구현한다. 사용자 운영 사이트에서 바로 켜지지 않도록 독립 개발 브랜치/테스트 빌드에서만 적용한다. 기존 저장된 필기 좌표와 주석 스키마는 절대로 변환·마이그레이션하지 않는다.

## 5. M4 구체 작업

### M4-1. 실제 함수 연결 지점 매핑
- 기존 서브노트·교재 PDF 표시 함수, 페이지 식별자(pageToken), Drive fileId, 취득된 원본 PDF Uint8Array 전달 위치 조사.
- Apps Script 원본 조회의 서명/nonce/ACTIVE 검증 흐름을 우회하지 않고 기존 API 그대로 호출.
- PDF 보기 버튼, 페이지 이동, 상태·오류·복구 UI를 보존한다.
- 정적 파일 캐시는 versioned JS/WASM만 허용, signed GET URL과 사용자 원본 PDF/필기 데이터의 캐시 금지.
- 기존 인증·권한·저장 경로를 직접 고치지 않는다.

### M4-2. MuPDF 공통 렌더러 UI 연결
- M3 API 사용: createMuPDFEngine, createMuPDFWorkerEngine, createUnifiedRenderer.
- 비운영 테스트에서 기본 MuPDF Worker, 실패 시 안전한 main-thread MuPDF 또는 PDF.js 6.5.438 대체 경로를 명확하게 표시.
- 기존 PDF.js fallback의 CVE-2024-4367 위험을 해소해야 하며 구형 3.11.174를 무방비 상태로 재사용하지 않는다.
- 로그인 없는 사용자에 대한 기존 학습정보 조회 정책 유지. 소유자 외의 추가/수정/삭제는 기존 서버에서 계속 차단.
- 실제 학습노트 HTML 전체를 무분별하게 교체하지 말고 최소 연결 수정 및 별도 모듈 분리.

### M4-3. 확대·축소 및 필기 좌표
- 최초 PDF 열기부터 MuPDF로 **고화질 렌더링**, Google PDF 뷰어로 전환하지 않는다.
- CSS zoom, devicePixelRatio, 실제 출력 픽셀/해상도, fitScale 분리.
- 고배율에서는 M3의 normalized region/tile을 사용하여 가시 영역 중심으로 디테일 유지.
- 기존 schema 3 normalized-0-1, stroke widthN, pressure, S Pen 포인터, 선/도형, 주석 저장/복원 경로 보존.
- 페이지 회전·CropBox·스크롤 오프셋·터치/핀치/마우스 드래그 시 오버레이 정합성 비교.
- 페이지·뷰어 전환 시 오래된 요청 취소, Worker 및 Document/Page/Pixmap 해제.

### M4-4. 독립 브라우저·기능 검증
- 실제 Chrome PC의 독립 loopback 브라우저에서 합성 PDF와 허용된 비공개 샘플로 렌더·확대·전환·주석 좌표 검증.
- 실제 개인 PDF/원본 조회가 필요하면 비공개 승인된 읽기 전용 경로만 사용하고 인증정보, PDF 또는 screenshot을 GitHub 업로드하지 않는다.
- 테스트 원본과 기존 필기 JSON은 변경하지 않고, 좌표·page identity 일치 여부를 비교한다.
- 자동검사와 PC 실제 브라우저 검사를 분리 보고한다.
- Galaxy Tab S11 및 iPhone 16 Pro 실제 펜·터치 검수는 M6/M7 집중. 수행되지 않았으면 미실시로 명시한다.
- 렌더링 실패 시 이전 UI 무손상, 원본 표시/복구 상태 일관성 확인.

### M4-5. 성능·안전
- M3 maxPixels/maxEdge/maxBytes에 따라 실제 출력 픽셀 제한.
- 타일 scheduling/재사용과 취소 규칙 구현.
- 대형 PDF, 여러 페이지 전환, 대기 상태에서 메모리 누수 방지.
- 원본 데이터·첨부·학습 상태 추가·수정·삭제 트리거가 새 렌더러 경로에서 실행되지 않도록 확인.
- 비밀정보·서비스워커 개인정보 캐시 위험 점검.
- M1/M2/M3 핵심 회귀검사 재사용, 불필요한 전체 UI 검증 반복 금지.
