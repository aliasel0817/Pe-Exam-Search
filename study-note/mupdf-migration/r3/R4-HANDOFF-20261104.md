## 4. R4-0 — 실제 운영 출시 전에 반드시 해소할 차단 조건

1. **Artifex/법률:** 브라우저 MuPDF와 Apps Script 분리 API의 AGPL 결합 범위, 공개 Corresponding Source 범위, 필요 시 상용 계약을 적격 서면으로 확정.
2. **재현 가능 WASM:** Linux + EMSDK 4.0.8 + 정확한 upstream 소스 18개 submodules에서 실제 `npm run prepack`; 결과 JS/WASM의 SHA-256 기록 및 M2 배포본 차이 분석. `platform/wasm`의 npm lock 부재 보완.
3. **제3자 라이선스/NOTICE:** 실제 폰트·CJK·ICC·하위 모듈의 정확한 고지·소스/라이선스 충돌 및 공개 제공 방법 검토.
4. **비밀정보 분리:** Corresponding Source에 Script Properties/OAuth·HMAC·서명 URL·사용자 PDF/시트/주석 정보가 절대 포함되지 않는지 검증.
5. **운영 보안:** 읽기 전용 버전21 소스 정적검사와 실제 운영 ACTIVE 인증 성공을 구분하고, 격리 계정·승인·백업/복원 조건에서 안전한 owner-only/필기 저장 검증.
6. **실기기:** 적법한 비공개 방식으로 Galaxy Tab S11 실 S Pen/손바닥 및 iPhone 16 Pro 실제 Safari 핵심 검증, 불가할 경우 별도 서면 위험판단/필수 차단 조건 유지.
7. **통합 의존성:** 모든 누적 PR과 Actions, 이전 학습정보·인증·상태·필기 schema 회귀 영향 확인.
8. **복구:** 운영 Apps Script 배포 ID/버전, GitHub Pages 이전 버전, 주석/학습데이터 백업·복구 계획 확보.
9. **별도 사용자 승인:** 구체적인 승인 대상(어느 SHA/PR, Apps Script 버전/배포, GitHub Pages, MuPDF 공개 범위)을 사용자에게 제시해 명시 승인 확인.

하나라도 미해결이면 **운영 NO-GO**, 외부 제공·실사용 데이터 쓰기 및 병합·배포 차단.

## 7. R4-3 — 별도 명시 승인 후에만 운영 반영

**다음 조치는 승인되기 전에는 절대 실행하지 않는다.**

1. 사용자에게 승인받은 정확한 GitHub SHA/PR 목록과 변경 영향·복구 계획을 재확인.
2. 사전 백업 및 원본/필기·인증 안전성 확인.
3. 승인된 누적 PR 의존성을 정리하여 대상 main에 안전하게 병합.
4. 승인이 필요한 경우에만 Apps Script 코드 push, 버전 생성, 기존 배포 ID를 통한 버전 갱신. 서명/비밀정보·사용자 원본/ACL 변경 금지.
5. 승인된 GitHub Pages 배포 및 필요한 MuPDF JS/WASM 공개. 법률 근거/소스/고지/비밀정보 차단이 충족되지 않았으면 즉시 중단.
6. 최종 commit 및 GitHub Actions 모두 확인.
7. 실제 운영 사이트에서 서브노트·교재·첨부 PDF 첫 로딩 고화질, 확대, 페이지/첨부 전환, 기존 PDF.js fallback, 필기 저장·복원 주요 기능 확인.
8. Windows PC·Galaxy Tab S11·iPhone 16 Pro 실기기 검수를 수행하고 자동검사/에뮬레이션 결과와 분리 기록.
9. 오류 발견 시 사용자 승인된 범위의 안전한 복구·롤백 절차 실행. 공용 서비스 임의 재시작/다른 채팅 PID 종료 금지.

R4는 단순 PR 생성과 배포를 동일시하지 않는다. **실제 서버/GitHub Pages까지 확인하지 않은 경우 운영 완료를 선언하지 않는다.**
