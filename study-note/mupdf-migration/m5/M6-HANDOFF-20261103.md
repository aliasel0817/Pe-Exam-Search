## 0. 최우선 작업 지시

M0~M5의 최신 **실제** 소스·브랜치·PR을 다시 확인하되 이미 검증한 구현을 불필요하게 다시 개발하거나 반복 조사하지 않는다. M6는 세 가지 PDF 보기(서브노트·교재·첨부 PDF)를 PC·태블릿·iPhone에 맞게 성능과 필기·제스처 면에서 안정화하는 **개발 중심** 단계다.

특히 기존 주석 스키마 3 / normalized-0-1 좌표, 사용자 필기 데이터, LIVE MASTER, Drive PDF·이미지·첨부, 인증과 서버 owner-only 권한을 보호한다. 실제 서버 인증정보나 필기 동기화 데이터를 테스트 산출물에 노출하지 않는다.

**MuPDF.js AGPL 대응 소스 공개 범위가 아직 법적으로 최종 확정되지 않았으므로 외부 공개 서버나 GitHub Pages에 MuPDF JS/WASM을 배포하지 않는다.** 실제 외부 기기에 대한 바이너리 전송은 라이선스·비공개 테스트 환경 적합성을 먼저 확인한다. 법적 확인 없이 LAN 서버를 공개 가능한 서비스로 간주하지 않는다.

## 4. M6 상세 개발 목표

### M6-1. 세 뷰어의 공통 동작 점검 및 필요한 결함 수정

- 기존 M4 서브노트·교재와 M5 첨부 PDF 공통 UI, M3 Worker, PDF.js fallback의 실제 의존관계를 확인한다.
- 동일한 구현을 재작성하지 말고, 기기간 차이가 확인된 기능만 최소 수정한다.
- 페이지 전환, 선택, 리사이즈, 회전, 화면 비율, 확대·축소 시 상태 관리 차이를 정리한다.
- PDF.js 3.11.174 운영 기본값을 임의로 배포 변경하지 않는다.

### M6-2. S Pen·손바닥 방지·주석 위치 정합성 안정화

- Galaxy Tab S11에서 펜과 손바닥이 동시에 인식될 때 필기 손실, 의도치 않은 화면 이동, 터치 오인식을 방지하도록 기존 `installPdfPanPinchHandlers`, `annotationTouchZoomAdapter`, 관련 입력 로직을 필요한 범위에서 보완한다.
- 펜 굵기, 필압, 형광펜, 선/도형, 지우개, 텍스트/메모, 선택·편집을 보존한다.
- `schemaVersion=3`, `normalized-0-1` 및 저장된 object ID/page key는 변경 금지.
- CropBox·회전·DPR·fitScale·zoom·세로/가로 화면 전환에서 PDF와 ink overlay의 픽셀 위치 오차를 측정하고 필요 시 **표시 계층만** 수정한다.
- 실제 저장된 사용자 필기에 대해 강제 데이터 이관/수정/삭제하지 않는다.

### M6-3. iPhone Safari와 PC의 제스처·뷰포트 안정화

- iPhone 16 Pro Safari의 Touch Events/Pointer Events, 한 손가락 스크롤/두 손가락 핀치, 안전영역(safe area)과 회전, 디바이스 DPR/visualViewport 차이를 분석하고 실제 문제를 수정한다.
- Chrome Windows PC 마우스 드래그·휠·단축키 및 모달 높이·스크롤 연동을 유지한다.
- 단순 에뮬레이션은 실제 기기 테스트로 기록하지 않는다. 물리적 기기를 제어할 수 없는 경우 해당 검사를 **미수행**으로 명확히 보고한다.

### M6-4. 고배율 화질·메모리·Worker 성능 개선

- 확대 2x, 4x, 8x, 10x에서 글자 선명도·타일 경계·주석 정합·뷰어 응답 시간을 계측한다.
- Worker 취소·문서 close·page switch에서 WASM/Canvas 메모리 해제, 이전 요청 잔여 타일·중복 재렌더 제거를 개발하고 테스트한다.
- 모바일 메모리 예산을 기기별로 조정하되 원본 PDF 품질과 기존 주석 데이터는 변경하지 않는다.
- 대형 첨부 PDF, 다중 문서 전환, 빠른 페이지 변경, 화면 가로/세로 회전 후 중단 없는 렌더링을 목표로 한다.
- 1MB 이상 이미지 WebP 최적화 등 무관한 기능은 변경하지 않는다.

### M6-5. 실제 PDF·인증된 읽기 경로 확인 (승인·비밀 보호 조건)

- 실제 사용자 인증을 테스트할 수 있는 장비와 명시적으로 허가된 PDF에 한해 **읽기 전용** 원본 `referencePdfContent` signed GET 및 `mediaContent` GET을 확인한다.
- ACTIVE 기기 서명, sourceType/pageToken/attachmentId, 인증 만료·에러 처리를 유지한다.
- 운영 Apps Script의 `doPost` 권한/기기 상태/owner-only 변경 API는 수정·호출 금지.
- 사용자 토큰, 응답 base64, 개인정보나 실제 필기 파일을 GitHub/CI/로그에 업로드하지 않는다.
- 실사용 주석 저장/복원 통합 테스트가 필요하다면 별도 격리 테스트 계정/복사본과 데이터 보존·복구 계획을 우선 마련하고, 실제 LIVE MASTER나 본인의 실필기를 임의 수정하지 않는다.

### M6-6. AGPL 및 공개 테스트 경계

- Artifex 또는 자격 있는 법률 전문가 확인이 필요한 핵심 문제: MuPDF JS/WASM과 Apps Script HTTP API의 결합 관계, 대응 소스 공개 범위, WASM 재빌드 원본/스크립트, 프런트엔드와 서버의 설정·비밀 분리.
- 이 문제가 미해결이라면 **웹서버를 통한 외부 공개, 공개 LAN/인터넷 프리뷰, 제3자 기기로의 바이너리 배포를 완료로 선언하지 않는다**. 로컬 Chrome/가상 브라우저 검증은 독립 격리 상태로 유지한다.
- M2의 배포 차단 게이트·AGPL 고지·소스 제공 초안을 그대로 유지한다.

## 8. 안전 규칙

- LIVE MASTER 원문, Drive 원본 PDF·이미지·첨부파일·학습정보·실사용 주석 임의 추가·변경·삭제 금지.
- 인증·권한·Apps Script 설정 및 보안 비밀 변경·공개 금지.
- 다른 채팅의 작업 폴더/브랜치/터미널 세션/PID/사용자 미커밋 보존.
- Git reset/clean/force, 소유권 모호한 프로세스 종료, 공용 서비스 재시작 금지.

- M6까지만 진행, M7 개발·운영 적용은 시작하지 않음.

## 9. 최종 지시

**M6 범위의 호환성·주석·터치·고배율·메모리 최적화 개발을 실제로 완료 가능한 수준까지 수행하고, 핵심 검증 및 Draft PR 제출 후 M7 전체 인계서를 작성한다.** 기기·법률 제약으로 불가능한 검증을 가상의 합격으로 보고하지 않으며, 외부 공개/운영 배포는 사용자 명시적 별도 승인 전까지 절대 진행하지 않는다.
