## 3. 반드시 해결할 출시 차단 조건

### 법률·권리

1. AGPL 공개 소스 준수 방식 또는 Artifex 상용 라이선스 중 선택.
2. AGPL 경로라면 Artifex/적격 전문가의 앱·Apps Script 결합 및 대응 소스 범위 판단, 실제 배포 버전의 전체 대응 소스·NOTICE·변경·소스 접근 공지, 비밀정보 격리 확인.
3. 상용 경로라면 계약 대상·사용 범위·배포 형태와 실제 계약 체결 확인.
4. 어느 경로든 저작권/라이선스·제3자 고지 보존. 운영에서 최초로 사용자가 실제 소스 링크에 접근 가능한지 확인.

### WASM 출처·빌드

1. R3 확보 MuPDF 1.28.1 tag `20061bd45183f5a2bff8f43675e4da91e5ac2901`, thirdparty 18개를 비공개 승인 Linux EMSDK 4.0.8 환경에서 실제 `npm run prepack`으로 빌드.
2. 비밀정보/원본 데이터 제외, npm 의존성 잠금/설정/패치/소스 대응 관계, 결과 바이너리 해시·차이 원인 기록.
3. **바이트 단위 동일 해시는 필수 법률 요건이 아니라 권장 기술 증거**. 공식 FSF GPL FAQ 기준으로 완전한 Corresponding Source가 핵심.

### 실제 인증·주석·기기

1. R2에서 운영 기본 API가 Apps Script 배포 버전21과 일치하고 health 원본 PDF 가능 `true`인 사실 재사용. **운영 ACTIVE signed GET 실제 PDF bytes는 미검증**, GET가 기기 마지막접속시각을 수정할 수 있음.
2. 별도 승인된 격리 기기·계정·PDF·복구 수단이 마련된 경우에만 ACTIVE/PENDING/REVOKED, owner-only, schema3/normalized-0-1 주석 영속 저장·복원 수용검수.
3. 물리 Galaxy Tab S11 실제 S Pen/손바닥·핀치/회전, iPhone 16 Pro 실제 Safari/WebKit 확인. 에뮬레이션 PASS로 대체하지 않는다.
4. R3 캐시 선점 문제는 격리 후보에서만 개발. 실제 운영 Code.js 패치는 별도 설계/동의/nonce·등록 멱등성 검증 없이는 적용하지 않는다.

## 5. 원격 PC 다중 채팅·할루시네이션 방지

- User chat 인계의 SHA/PR/CI/운영 버전은 과거 단서이며 착수 시 실제 검증 우선.
- 실제 공개 라이선스 URL·서면 계약 없는 상태를 법률 GO로, source hash를 C 재빌드 성공으로, health=true를 실서버 원본 PDF 성공으로 보고 금지.
- 실제 Safari/iPhone·S Pen 물리 검수와 Chrome touch 에뮬레이션 구분.
- 빌드 환경이 없으면 WASM 재빌드 NOT VERIFIED/BLOCKED. 비밀정보 검사 0건을 모든 비밀정보 안전 증명으로 판단 금지.
- LIVE MASTER/Drive/원본 PDF/기존 주석 schema3/normalized-0-1 및 owner-only 정책 보호. 인증서명/PDF 바이트/시트 데이터·사용자 필기를 Git/PR/CI/로그에 올리지 않음.
- 다른 채팅의 폴더/미커밋/PID/터미널/서버/설정을 조작하지 않음. 소유권 불명확한 프로세스 종료 금지.
- R5 종료 시 전체 M0~R5 완료/미완료, 다음 단계 R6 필요 여부, 자동검사 vs 실제 기기, 측정하지 않은 시간의 추정비율 금지.

**R5 요청서를 복사했다고 해서 운영 반영이 자동 승인되거나 배포가 진행되는 일은 없다.**
