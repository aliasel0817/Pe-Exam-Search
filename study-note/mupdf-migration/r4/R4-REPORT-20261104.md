## 2. 라이선스 법률·기술 분석의 정확한 결론

- `mupdf@1.28.1`는 `AGPL-3.0-or-later` 또는 Artifex 별도 상용 라이선스 모델. 브라우저로 MuPDF JS/WASM을 제공하면 소스 공개·고지 의무가 문제되며, Artifex는 서버 앱의 자체 소스 공개 필요성을 명시.
- 따라서 **MuPDF 라이브러리만 공개하고 앱 코드를 비공개 유지하는 방식을 곧바로 AGPL 준수로 승인할 수 없음**. 별도 Apps Script HTTP API가 AGPL 결합 소스 범위에 포함되는지는 해당 구조에 대한 Artifex/전문가 서면 판단이 필요.
- 사용자 원본 PDF·Sheet 데이터·실사용 필기·Script Properties/HMAC/계정 비밀은 소스 공개 대상이 아니며, 비밀을 제외한 코드·설치 방법·예시 설정이 실제로 충분해야 함.
- **정정:** R3의 byte-for-byte WASM 동일성을 별도 절대 출시 법률 요건으로 다룬 부분은 과도함. GNU FAQ는 바이너리와 동일 SHA-256 재현을 엄격한 법적 필수 조건으로 보지 않음. 그러나 실제 WASM 대응 소스·빌드 스크립트·배포물의 출처 증거와 사용자의 수정/빌드 가능성은 아직 확보되어야 함.
- Artifex Producer line/PDF metadata 권고는 원본 PDF 생성·수정과 관련. 학습노트에서 **기존 원본 PDF 메타데이터는 수정하지 않음**.
- **권고:** Apps Script 보호 소스를 비공개로 유지해야 하면 Artifex 상용 계약이 더 예측 가능. AGPL을 선택한다면 앱·백엔드 결합 범위에 대한 적격 판단과 완전한 대응 소스 공개 절차가 필요.
- 최종 고지·대응 소스·AGPL 사용 적합성/계약은 **아직 확정되지 않았으며 공개 배포 NO-GO**.
