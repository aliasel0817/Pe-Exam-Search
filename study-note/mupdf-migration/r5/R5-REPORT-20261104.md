## 2. 확인된 사실과 별도 위험

- R2 Apps Script snapshot 두 사본(HEAD/version21)은 당시 동일한 Code.js hash. **현재 운영 GAS 배포 코드와 동일한지는 R5 시점에서 재조회 필요.**
- 최초 출처: Artifex 공식 MuPDF 1.28.1 `20061bd...`, npm `mupdf@1.28.1` JS/WASM 고정 SHA. 이는 실제 C→WASM 빌드 성공과 다른 증거.
- Windows 원격 PC에 Linux WSL 배포판과 emcc가 없어 **로컬 C→WASM 빌드는 BLOCKED**. GitHub Actions Linux builder가 최종 SHA에서 실행된다면 해당 결과를 별도로 확인.
- `R5-CORRESPONDING-SOURCE-ACCESS.md`의 공개 후보 문서는 최종 배포 바이너리/정확한 source offer가 완전하다는 주장이 아니다. 최종 main 반영 시 고지 URL을 그 배포 commit/ref와 연결해야 함.
- AGPL 방식은 프로젝트 소유 source 공개 선택을 반영하지만 모든 서드파티 권리·서버 결합·인증 보안·필기 안전이 자동으로 해결되지는 않음.
- Android Galaxy Tab S11 실 S Pen·iPhone 16 Pro Safari 물리 검수와 격리 ACTIVE signed GET/owner-only/클라우드 필기 저장 복원은 **미검증**. 실제 GET 시 보안 기기 마지막 접근 시간이 바뀔 수 있어 무단 호출 불가.
- 세 PDF 뷰어 기본 개발은 M1~R4에서 완료되었지만 R5의 현재 UI는 여전히 loopback opt-in 게이트가 적용됨. GitHub Pages 고화질 MuPDF 자동 활성·JS/WASM public release는 별도로 완성·검증할 것.
- 사용자 원본 LIVE MASTER·Drive PDF·첨부·필기·기존 사용자 데이터·운영 Apps Script 설정을 수정하지 않음. R5 main merge 여부는 실제 GitHub 상태로 확인 전까지 완료로 기재하지 않음.

## 4. 출시 GO/NO-GO

**개발 소스 공개 준비 및 기술 검증 =/= 최종 운영 출시 GO.**

서버 코드까지 코드 후보를 공개하는 선택과 실제 MuPDF JS/WASM을 운영에 공급하는 행위는 다르다. 실제 Linux 컴파일·비밀정보/권리·실제 배포 버전 소스·주석/인가·운영 브라우저 검수와 최종 승인 조건이 해결되기 전에는 R5 독립 브랜치에서 검증하고 **main merge 및 Pages MuPDF 배포는 NO-GO**로 유지한다.

사용자의 AGPL 공개와 main 반영 승인은 인지하였으나, 불충분한 대응 소스/비밀정보 유출 위험을 무시하는 승인으로 해석하지 않는다.
