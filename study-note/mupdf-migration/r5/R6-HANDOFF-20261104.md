## 2. 우선 해결할 AGPL 공개·WASM 조건

1. R5 `source/Code.js` 정확한 SHA가 운영 버전 21과 같은지 **현재** Apps Script read-only로 재검증. 코드 전체 공개 전 비밀정보·권리 수동/자동 검사; Script Properties·키·사용자 데이터 분리.
2. Artifex AGPL 안내에 따라 프런트+Worker+MuPDF JS/WASM+관련 Apps Script 전체 해당 소스 범위 확인. R5 공개 코드 후보와 설치/수정/빌드 스크립트의 대응관계 검증. 완성되지 않은 source offer를 고지 링크로 사용 금지.
3. **실제 C→WASM 재현 빌드는 R5에서 3개 JS/WASM npm SHA까지 모두 일치 PASS 완료.** 동일 빌드 입력을 수정하지 않는 한 중복 빌드 금지. R5 빌드 로그와 정확한 소스·18개 submodules/emsdk/npm lock·산출 SHA를 불변 릴리스 자료로 연결하고, 출시 바이너리/대응 소스 URL의 실제 일치 여부를 검증. 바이트 동일 해시는 이미 확보한 강력한 기술 증거로 유지하되 독립 AGPL 법률 요건이라고 잘못 설명하지 않음.
4. 폰트/CMap/ICC·libjpeg IJG 및 기존 PDF.js/pdf-lib/SheetJS 최종 NOTICE와 권리 확인. 사용자 보유 앱 소스에는 `AGPL-3.0-or-later` 적용, thirdparty 원래 저작권 존중.
5. 정확한 main 출시 commit/version을 가진 **실제 공개 Source Offer URL**을 구현/시험. R4 고지 UI를 안전하게 운영 노출하고 사용자에게 라이선스 전문·Corresponding Source 링크·무보증/변경 고지 제공. JS/WASM 공개는 법률·보안 게이트 충족 뒤에만.
6. 운영의 PDF.js 구버전 위험과 새 fallback 6.5.438를 구분해 최종 전환/복구 보안 검증.

## 3. 세 PDF 고화질 운영 연결 개발 (새로 재개발 금지)

- 현재 M4·M5·M6가 loopback `m4-local=1&m5-local=1&m6-local=1`로 게이트됨. 사용자에게 공개되는 GitHub Pages 기본 URL에서 고화질 MuPDF 초기 렌더를 지원하도록 안전한 운영 모드 연결을 구현하고, M2/R4 release gate와 승인 조건을 훼손하지 않는 배포 패키징 개발.
- R3/R5 빌드된/검증된 JS/WASM과 해당 source offer가 실제 동일 릴리스임을 확인.
- referencePdfContent signed GET, mediaContent, 주석 schema3/normalized, 페이지별·첨부별·사용자별 key, 펜·형광펜·되돌리기, 원본/기존 PDF·자료·인증/owner-only 권한 보존.
- Worker 실패 시 안전 PDF.js fallback, CropBox·rotation·4x/8x/10x tile, 페이지/문서 변경 취소, Service Worker가 원본 PDF/서명/토큰을 캐시하지 않는지 확인.
- 중요 결함만 실제 코드로 수정하고 관련 최소 테스트 추가. 기존 M1~R5 정상 기능을 재개발하지 않음.

## 5. main 반영·Apps Script·Pages 승인 안전 조건

R5에서 사용자가 AGPL 공개 및 main 반영을 요청한 사실은 유지. 그러나 새 배포 대상/source/차단 문제는 실제 diff와 빌드 근거를 확인해 정확한 영향 범위를 사용자에게 보고해야 한다.

1. GitHub Pages 자동 배포 트리거·현재 main SHA·기존 운영 Apps Script 배포 ID/버전·기존 주석/시트/Drive/이미지 보존 및 복구 방안 확보.
2. 누적 PR #52→#63→R5→R6는 **동일 integration base에 대한 누적 PR**이므로 중복 squash 병합을 금지하고 **최종 누적 트리**의 검증된 커밋/차이로 단일 안전한 main 통합 계획 수립.
3. 모든 필수 조건이 실제 증거로 통과했다면 승인 범위 안에서 main 병합. Apps Script 수정·버전·배포와 MuPDF 바이너리 공개는 각각 범위가 명시적으로 승인됐는지 확인.
4. 병합 후 GitHub Actions·Pages 실제 반영 commit, 실 서비스 고화질·원본/필기 데이터·실기기 수용검수 결과 확인.
5. 장애 시 승인된 revert/복구 커밋 및 이전 Apps Script 버전 복귀 경로. Git force/reset, 사용자 데이터 임의 롤백 금지.
6. 조건 미달이면 **main/Pages/MuPDF 공개 NO-GO**; 개별 준비 완료를 운영 완료로 보고하지 않음.
