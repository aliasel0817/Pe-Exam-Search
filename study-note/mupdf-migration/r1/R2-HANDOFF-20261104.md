## 0. 최우선 지시: 기존 완료 소스 재사용 및 개발 우선

M0~R1을 다시 개발하지 않는다. 이미 통과한 53개 R1 관련 단위검사 및 물리 Windows Chrome 합성 PDF 결과는 증거와 변화 범위가 확인되면 재사용한다. 같은 합성 PDF의 전수 확대, 수백 페이지 반복, 장시간 성능, 다중 브라우저 조합, 사소한 UI/레이아웃 반복 검수는 R2 개발 차단 이유가 되지 않는다면 **후속 승인된 실사용 검수로 이관**한다.

## 4. R2 개발 우선순위 1 — 실제 운영 코드·배포 버전 동등성

운영 Apps Script에 **쓰기 없이** 현재 프로젝트 식별·배포 버전·실행 소스의 근거를 확인한다.

- 기존 로컬 사본 예: `Pe-Exam-Search_issue45_apps_script_source_20261102_chat`, `...deployed_v20...`, `...postpush...`, `...candidate...`. 이 폴더는 **다른 채팅 소유**이므로 변경하지 않음.
- R0 정적 감사에서 source/deployed_v20과 postpush/candidate 코드 해시가 달랐음. 어느 버전이 실제 운영 실행본인지 예측하지 말 것.
- R0의 `clasp deployments --json` 결과는 배포 2개/버전 번호 21. 버전 번호만으로 실제 코드 해시 동등성·현재 활성 URL/함수 동작 확정 금지.
- 연결된 Apps Script 프로젝트의 최신 `Code.gs`/배포 버전을 **허용된 읽기 전용** 경로로 확인할 수 있는 경우에만 근거 비교.
- 권한이나 네트워크로 확인 불가하면 `NOT VERIFIED` 기록. 운영 Script Properties, API keys, signed token, 원본 PDF bytes, OAuth refresh token은 출력·PR·로그 업로드 금지.
- 함수 식별/메서드명은 실제 서버 소스를 읽은 뒤에만 사용한다.
- 차이를 발견하면 운영 코드를 덮어쓰지 말고 **독립 로컬 패치 후보/검증 코드**로 개발한다.

## 5. R2 개발 우선순위 2 — 원본 PDF read path 통합 결함 수정

실제 서버 및 UI 코드에서 결함이 확인되는 경우에 한해 수정한다.

**서브노트·교재**
- ACTIVE 기기의 signed GET로 `referencePdfContent` 원본 PDF 조회, 출처유형·페이지토큰 검증.
- Drive ID는 서버 측 신뢰 데이터로 결정, 클라이언트가 제공하는 파일 ID를 신뢰하지 않음.
- capability `referencePdfContentReady`의 최신 운영 값 확인(실제 응답을 확인 못하면 추측하지 않음).
- 인증 실패/만료/원본 없음/용량 제한 등 오류에서 기존 미리보기와 안전 fallback 경로 보존.
- 페이지 이동·확대 시 불필요한 재호출/중복 렌더 제거 (실제 코드/재현 근거가 있을 때).
- 메인/첨부 renderer가 이전 signed URL·bytes·Worker 작업을 캐시하거나 공개 로그로 기록하지 않도록 유지.

**첨부 PDF**
- 기존 mediaContent GET, MIME/PDF header/size, 첨부 ID·페이지별 주석 key·페이지 전환 동작 보존.
- 원본 사용자 PDF/Drive 파일을 임의 다운로드·저장/유출하지 않는다.
- 기존 공개 조회 허용 정책을 근거 없이 차단하지 않는다.

R1에서 완료한 Worker/tile/scroll 수정은 그대로 재사용한다.

## 6. R2 개발 우선순위 3 — 권한 및 필기 영속성 안전 경계

코드 레벨에서 아래 정책의 실제 구현을 분석해 필요한 **격리 브랜치 후보 수정**만 수행한다.

- ACTIVE/PENDING/REVOKED 장치 상태, signed GET/POST HMAC, TTL, nonce 재사용·서명 위조·만료 검증.
- owner-only 데이터 추가·수정·삭제 정책 보존; 공개 조회 허용 부분은 보존.
- 기존 R0 경고인 ownerSub 직접 검증 위치와 인증 전에 발생하는 idempotency claim 경로에 실제 취약점이 있는지 함수별로 확인.
- 주석 schema3/normalized-0-1/사용자·페이지·첨부 key 불변, 펜·형광펜·Undo/Redo 동작 보존.
- 실서버 필기 **쓰기는 별도 사용자 승인과 테스트 사본·백업·복원·격리 계정이 모두 확보될 때만** 허용. 그 전에는 합성 메모리 내 자료 또는 안전한 분리 환경에서만 검사한다.
- 실제 사용자 데이터로 취약점 공격·권한 변경·PDF 교체 테스트를 하지 않는다.

## 8. AGPL 및 공개 차단 — R2 범위에서 절대 준수

M2 gate `BLOCKED_PENDING_ARTIFEX_LEGAL_REVIEW` 유지. npm MuPDF 1.28.1 gitHead와 upstream tag 일치는 대응 소스/법률 인증이나 WASM 재빌드 성공이 아님. Apps Script API 결합관계, 전체 Corresponding Source 범위, 정확한 C→WASM toolchain/패치·제3자 라이선스, user-visible NOTICE 및 소스 공개 방식이 미확정.

Artifex 또는 자격 있는 전문가 판단과 별도 사용자 명시 승인 전까지 **GitHub Pages/공개 테스트 서버/외부 사용자에게 MuPDF JS/WASM 송출 금지**. 법적 불확실성 때문에 실제 기기 접근이 불가능하면 검사 BLOCKED로 분류. 운영 main/integration 및 Apps Script 수정·버전·배포 역시 금지.

## 10. 할루시네이션 방지 규칙

- 이전 SHA/PR/배포 버전은 과거 시점 근거. 현재 원격 GitHub/실제 소스 확인을 우선.
- GitHub 푸시·PR 생성·Actions를 확인하지 않고 성공 보고 금지.
- Code.gs 원본을 확보 못 했다면 존재하지 않는 함수/기기 서명 정책을 추측하여 구현 금지.
- 기존 Code.js 사본 해시와 **실제 배포 바이너리/서버 실행본 동일성**을 혼동 금지.
- 코드를 읽었음 ≠ 운영 인증 성공, 브라우저 에뮬레이션 ≠ 물리 기기, npm gitHead 일치 ≠ WASM 재현 빌드, 0건 보안 탐지 ≠ 완전 무결.
- 비밀값·서명·signed URL·실사용 PDF bytes·주석 원본·사용자 정보는 CI/로그/GitHub/PR에 넣지 않는다.
- 실측하지 않은 시간 비율이나 메모리/성능 숫자를 만들어내지 않는다.
- 결과를 PASS/FAIL/NOT VERIFIED/BLOCKED/DEFERRED로 구분.
- 사용자 승인 없이 main/integration/Apps Script/Pages 변경·MuPDF 외부 배포 금지.
