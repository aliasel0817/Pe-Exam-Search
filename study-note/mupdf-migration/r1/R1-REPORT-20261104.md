## 2. 실제 수정한 결함과 코드

### A. 동일 Worker 중복 문서 열기 위험

- 파일: `study-note/mupdf-migration/m3/m3-worker-client.mjs`.
- 문제: `MuPDFWorkerSession._open()`이 동시 호출되면 `countPages`가 0인 동안 같은 Worker에 여러 `open` 작업을 넣을 수 있음. Worker는 하나의 세션 상태를 사용하므로 중복 open과 close가 경합할 위험.
- 수정: 미완료 open Promise를 `this.opening`으로 공유. 작업 취소·Worker 종료 시 해당 참조를 해제하고, 비정상 종료·중단 시 다음 open을 재시도할 수 있도록 함. 개별 signal 상태 재확인.
- 검증: 가짜 Worker에서 bounds/render가 동시에 시작되어도 open 요청 **1개**만 발생, 작업 완료 후 close/terminate 확인. 실제 Chrome의 기존 MuPDF Worker 렌더 경로도 PASS.

### B. 시작 시각 0에서 타일 이벤트 최대 대기시간이 늘어날 수 있는 문제

- 파일: `study-note/mupdf-migration/m6/m6-interaction-policy.mjs`.
- 문제: `createM6ScrollCoalescer()`의 `firstAt=0`과 `if(!firstAt)`가 실제 시각 0을 '기록 안 됨'으로 취급하여 지속 스크롤에서 최대 대기 보장이 흐트러짐.
- 수정: `firstAt=null`을 대기열의 미설정 sentinel로 사용, flush/cancel/close 시 동일하게 초기화.
- 검증: t=0/100/230/300ms 입력에서 예약 실행 시각 360ms 상한 확인. 실제 Chrome 65 스크롤 이벤트가 1개의 타일 스케줄 실행으로 합쳐지는 경로 PASS.

### C. 확대·viewport 재렌더 중 오래된 detail tile이 남는 문제

- 파일: `study-note/mupdf-migration/m5/m5-attachment-ui.js`, `study-note/study-note.html`.
- 문제: base 렌더와 detail tile을 다시 요청하는 동안 이전 확대 배율의 타일이 변경된 페이지의 위에 남을 수 있음. 필기 레이어보다 아래라도 시각적으로 잘못된 타일 표시가 가능.
- 수정: M5 `m5RepaintAttachment()`, M4 `m4RepaintReferencePdf()`에서 이전 detail tile을 새 paint 예약 전에 명시적으로 제거.
- 검증: 실제 Chrome 합성 PDF에서 첨부 확대 3→3.2 및 교재 확대 8→9 직후 이전 detail tile이 제거됨. 신규 타일 재생성 및 주석 최상위 z-order 유지 확인.
