**R3-1. MuPDF 원본/정확한 WASM 재빌드 증거**
1. 배포 예정 버전 `mupdf@1.28.1`의 공식 npm JS/WASM 체크섬과 정확한 Artifex tag `20061bd45183f5a2bff8f43675e4da91e5ac2901` 관계를 재확인.
2. 해당 1.28.1 릴리스의 정확한 C 원본, submodules, third-party 라이브러리, 패치, Emscripten SDK 버전, flags, scripts, feature definitions, build setup을 확보.
3. **허가된 PC의 독립 R3 로컬 폴더**에서 가능하면 재현 빌드 및 SHA-256 비교. 빌드 실패/OS 툴체인 부족이면 빌드 미검증으로 기록하고 추측으로 PASS 금지.
4. 바이너리는 `.r3-private` 등 Git 추적 제외 로컬 비공개 영역에만 보관. 공개 Actions artifacts·Pages·npm·PR에 업로드하지 않음.
5. 대응 소스/빌드 설치 가이드·검증 방법·누락 목록을 **비밀정보 제외** 형태로 산출한다.

**R3-2. AGPL 및 상용 라이선스 경계**
1. 실제 사용 구조: 브라우저 MuPDF JS/WASM ↔ 학습노트 프런트 ↔ Google Apps Script HTTP API ↔ Drive/Sheets 를 기능/배포/통신 단위로 정리.
2. 프런트/서버의 AGPL 결합 범위 및 API 별도 프로그램 여부는 **법률 문제**로 남겨 Artifex 또는 자격 있는 전문가에게 확인할 정확한 질문서 작성.
3. `AGPL-3.0-or-later`, NOTICE, 소스 제공 방법, 제3자 라이브러리와 프런트의 의무 충돌 확인.
4. 필요한 경우 Artifex 상용 라이선스의 대상·범위·공개 소스 의무 해소 조건을 검토하되 **서면 계약/판단 없이는 배포 가능 판단 금지**.
5. Google Script Properties·HMAC·OAuth client secret·사용자 PDF/필기/시트 내용을 공개 대응 소스에서 완전히 분리하는 구체적인 파일/정적 스캐너/샘플 설정안 준비.
6. 공개 대응 소스 패키지의 정확한 포함/제외 manifest, 설치·빌드·개발/재현 절차를 작성.

**R3-3. R2 보안 이슈의 안전한 후보 보완**
1. 서버 v21의 `doGet referencepdfcontent`는 ACTIVE `validateSignedGet_`와 서버 등록 시트 파일 ID 사용을 정적 확인했으므로 임의 재구현 금지.
2. R2에서 확인한 `doPost`의 `claimMutationRequest_`가 signed authentication 전에 CacheService를 사용하는 흐름을 격리 단위테스트로 분석. 이것은 **우회 성공이 아니라 사전 캐시 기록 위험**. 단순 순서 교체는 동일 nonce 재전송 시 멱등성 복구를 깨뜨릴 수 있으므로 동작 계약을 보존하는 최소 후보 코드/패치만 작성.
3. ACTIVE/ownerSub 인증·nonce/TTL/HMAC·기기 PENDING/REVOKED의 실제 보안은 사용자 자료로 공격 테스트하지 말고 합성 보안 컨텍스트로 확인.
4. 운영 Apps Script Code.js·배포 버전/설정은 수정·Push·배포하지 않는다.

## 4. R3 필수 인증/필기/실기기 출시 차단 해소

- R2 `health.referencePdfContentReady=true`는 원본 PDF 응답 성공·Google OAuth ACTIVE 검증을 증명하지 않는다.
- v21 `validateDeviceSignature_`의 `touchSecurityDevice_`는 조건에 따라 '마지막접속일시' 시트 값을 갱신한다. **ACTIVE signed GET도 운영 데이터 무변경 조건에 어긋날 수 있음**. 사용자 별도 명시 승인 또는 격리 계정·테스트 사본·백업/복구 조건 없이는 실행 금지.
- 실제 서버 원본 PDF byte·signed URL·Google 인증정보·Script Properties·사용자 주석은 로그/Git/CI에 남기지 않음.
- 실서버 주석 저장/복원은 별도 승인 + 격리 사본/계정 + 복구 체계 없이는 **BLOCKED**.
- Galaxy Tab S11 S Pen 실제 필압/손바닥, iPhone 16 Pro 실제 Safari WebKit은 실제 기기 연결 및 AGPL상 적법한 비공개 검수 환경 확보 시에만 핵심 수용검수. Chromium touch/UA 에뮬레이션을 실기기 검수로 보고하지 않음.
- 사용자 승인 전까지 어떠한 운영 동작도 변경하지 않는 R3 브랜치 내 작업만 수행.

**외부 공개·운영 GO**는 별도이며 반드시 다음을 만족해야 한다.
1. AGPL/상용 라이선스 적용 범위에 관한 적격 서면 판단, 실제 방식의 대응 소스 완전성·고지·빌드 근거.
2. 비밀정보와 사용자 데이터 공개 범위 분리 검증.
3. 운영 ACTIVE signed PDF, 실사용 필기/동기화 보존과 owner-only 접근 조건 해결 (안전한 승인 검수).
4. 물리 PC·Tab S11·iPhone Safari 필수 수용검수 또는 사용자의 분명한 위험 설명 수령과 별도 승인.
5. 모든 누적 PR 의존성·안전/복구·GitHub Actions 확인.
6. **사용자의 별도 운영 main 병합·Apps Script/Pages/MuPDF 공개 배포 승인**.

위 미해결이 하나라도 중요하다면 R3 개발 산출물은 완료할 수 있어도 운영은 **NO-GO**, 공개 배포·운영 설정 변경 절대 금지.

## 8. 할루시네이션 방지·원본 보호

- 과거 인계서/메모리/경로·SHA·PR·CI를 최신 상태로 추측하지 않는다. 실제 GitHub/물리 PC/운영 source read-only 증거 우선.
- 원본 Code.js/Google Script Properties을 읽지 못하면 없는 함수를 만들어내지 않는다.
- 소스 동등성 ≠ ACTIVE 인증 동작 성공, health capability true ≠ PDF byte GET 성공, 메타데이터 SHA ≠ WASM 재현, 정적 라이선스 ≠ Artifex 서면 판단.
- 운영 GET가 보안기기 마지막접속일시를 수정할 수 있음을 고려, '읽기 전용'이라는 용어를 HTTP method만으로 확정하지 않는다.
- 실기기 접근 불가를 에뮬레이션 PASS로 대체 금지. CI 미실행을 PASS로 기록 금지.
- 실제 파일·필기·학습정보·시트·서명 URL·세션 키·Google 로그인·비밀정보는 안전 승인 없이 읽거나 쓰거나 Git/PR/로그로 내보내지 않는다.
- 소스·설정·WASM 공개 배포/프로세스 종료·타 채팅 작업 변경 금지, 안전성 영향과 소유권 불명확하면 강행 금지.
- 완료된 기존 개발을 근거 없이 다시 미완료로 분류하거나 중복 검사하지 않는다.
