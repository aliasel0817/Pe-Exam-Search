## 1. 실제 운영 Apps Script 소스/배포 확인 — R0 미확정 일부 해소

- 과거 별도 채팅의 `apps_script_source`, `deployed_v20`, `postpush`, `candidate`는 **읽기 전용**으로 사용.
- 현재 허가된 PC에서 Apps Script `clasp deployments --json`을 **조회만** 수행: 배포 2개, 버전 21 존재.
- R2 독립 폴더의 Git 추적 제외 `.r2-private/`에 **서버를 변경하지 않는** `clasp clone <scriptId>` HEAD와 version 21 소스 스냅샷을 각각 생성.
- HEAD `Code.js` = 버전 21 `Code.js` = 과거 `postpush/candidate Code.js` (SHA-256 일치). 이전 버전 20 기준 소스와는 불일치.
- HEAD/버전21 `referencePdfContent.js` = `candidate/referencePdfContent.js` = Git 추적 중인 `study-note/backend/referencePdfContent.addon.gs` (SHA-256 일치).
- 운영 학습노트 `study-note.html`의 **기본 API URL**과 현재 Apps Script 배포 ID(버전 21)가 일치함을 로컬에서 **식별자 출력 없이** 확인. 사용자가 브라우저 localStorage로 별도 URL을 설정했는지는 확인하지 않았음.
- 이 기본 URL의 공개 읽기 전용 `?action=health` 응답에서 `ok=true`, `schemaVersion=15`, `referencePdfContentReady=true` 확인. PDF 응답/비밀정보/사용자 주석/개인 식별자는 저장하지 않음.
- 버전 21 `doGet`의 referencePdfContent 분기는 `validateSignedGet_(params,['ACTIVE'])`와 검증된 `verified.data`를 사용하고, 첨부 `mediacontent` 경로는 기존 공개 조회 정책대로 유지. 서버 측 `readReferencePdfPageForSignedGet_`는 등록 시트로 Drive 파일 ID를 결정.
- 버전21 `validateDeviceSignature_`에 TTL/nonce/HMAC 및 ACTIVE 검증, 등록 흐름에 ownerSub 확인 코드를 **정적으로 확인**. 운영 인가 실증과 같지 않음.

**실제 ACTIVE 서명 GET을 수행하지 않은 이유:** 버전21 `validateDeviceSignature_`의 `touchSecurityDevice_`가 조건에 따라 보안기기 시트 `마지막접속일시`를 기록한다. 따라서 현재 사용자 명령의 '운영 원본/사용자 데이터 변경 0'과 충돌할 수 있어 실제 기기 요청은 **NOT VERIFIED / 별도 명시 승인 전 차단**.

**추가 정적 관찰:** `doPost`는 서명/Google 등록 검증 전에 `claimMutationRequest_`로 CacheService에 요청 상태를 기록한다. 이는 R0의 `REVIEW_PRE_AUTH_CACHE_CLAIM` 경고 근거를 확인한 것임. 실제 권한 우회/데이터 변경이 성공한다는 증거는 아니며, 단순 순서 교체는 유효한 중복 요청의 nonce 재사용 거부 등 멱등성 부작용을 유발할 수 있어 운영 패치를 강행하지 않음. 별도 격리 보안 설계·검수 필요.

재현 가능한 프라이빗 메타데이터 감사 스크립트(원본 source는 Git·CI에 넣지 않음): `r2/r2-private-backend-audit.cjs`.

## 2. 실제 소스 수정 — 기존 3종 뷰어/필기 보존

변경 대상 `study-note/study-note.html`의 제한된 signed reference PDF fetch/렌더 경로:

1. `referencePdfSourceAbort` 컨트롤러 신규 도입; `resetReferencePdfHighQualityRenderer()`에서 이전 GET 취소. 페이지 전환/창 닫기 시 기존 reset을 그대로 사용.
2. `fetchReferencePdfBytesFromServer(page,{signal})`: 서명 생성 전·후/응답 수신 후/바이트 디코드 후 취소 확인. `fetch`에 `signal`, `cache:'no-store'`, `referrerPolicy:'no-referrer'` 전달.
3. 서버 응답의 `sourceType`, `pageToken`, MIME, size 검증을 기존대로 보존하고, **PDF %PDF- 헤더 확인을 렌더러 진입 이전으로 통일**.
4. `loadReferencePdfHighQuality()`(기존 PDF.js) 및 `m4LoadReferencePdfHighQuality()`(비공개 MuPDF)에서 동일 컨트롤러 연결, 취소 오류는 정상 페이지 전환으로 처리. 이전 요청의 finally가 새로운 요청의 로딩 상태를 덮어쓰지 않도록 동일 컨트롤러 검사.
5. 오류 로그는 전체 `Error` 객체 대신 코드/이름만 기록해 서명 URL 등의 상세정보 노출 가능성을 축소.

**운영 웹앱의 기존 원본 데이터/저장·권한 로직, JSON 필드, signed GET canonical 형식과 페이지토큰, mediaContent 경로, annotation schema3/normalized-0-1, 사용자별/페이지별/첨부별 키는 변경하지 않음.**
