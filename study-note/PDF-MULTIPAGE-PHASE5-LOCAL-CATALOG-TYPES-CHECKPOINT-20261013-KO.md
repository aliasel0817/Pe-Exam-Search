# 학습노트 PDF 기준키 안전성 5차 — 로컬 페이지키 자료유형 복구 (2026-10-13)

## 1. 발견
- 기존 `referencePdfCatalogFromLocal()`는 로컬 IndexedDB에서 PDF 키의 페이지번호·범위만 추출하고 **자료유형(materialType)은 반환하지 않음**.
- 바로 직전 배포 후보 `4.6.12-pdf-reference-base-key-guard`의 `isReferencePdfOriginalBaseKey()`는 자료유형이 `원본`이어야 기준 원본으로 표시함.
- 서버 페이지키 카탈로그 조회 실패 시 로컬 대체 목록에서는 모든 자료유형이 공란이므로 원본 키까지 드롭다운에서 사라질 위험. **운영 사용자에게 보고된 실제 장애는 없음. 자체 회귀검수에서 발견한 문제.**
- 앱은 오프라인 상태에서 PDF 업로드를 허용하지 않음. 다만 로컬 PDF 관리 화면의 기준키 표시 일관성과 일시적인 서버 카탈로그 오류 회복을 위해 보완.

## 2. 수정
- 프런트 후보 `4.6.13-pdf-local-catalog-types`.
- 로컬 PDF 파일을 출처유형+페이지키로 묶을 때 각 페이지의 자료유형(원본·보강·개정)을 함께 수집.
- 한 페이지키에 **개정 첫 장 + 보강 계속 페이지**가 공존하면 `개정`, 원본 페이지가 있으면 `원본`, 그 외는 `보강`으로 분류.
- 과거 캐시에서 자료유형이 공란이면 기존 원본으로 취급해 하위 호환성 유지.
- `-ADD숫자`와 `-R숫자`는 분류값과 관계없이 기존의 원본기준키 안전 필터로 차단.
- pageCount / 원본 페이지번호 범위 / 출처유형 / 순서 / 기존 파일과 토픽 연결 불변.
- Apps Script 변경 없음, 기존 PDF 페이지키·원본 시트 수정 없음.

## 3. 회귀검증
- 자동 테스트에 서버 카탈로그가 아닌 **로컬 폴백 경로**의 `referencePdfCatalogFromLocal` 실제 함수를 포함.
- 기존 교재 원본 SW:1~2, 보강 SW-2-ADD1:1~2, 개정 SW-R3 첫 장과 보강 계속 장, 미완성 SW-R4 보강 장, 오래된 서브노트 MG(자료유형 공란) 모의 목록으로 자료유형 복구 및 선택 목록 검증.
- 기존 교재·서브노트 PDF 자동 분할, 개정 표지 마지막 등록, 부분실패 재시도, 서버 재조회, 가독성 보호 테스트 유지.
- **구형 기기/모바일에서 네트워크를 실제 끊는 검증은 미실시**, 로컬 시뮬레이션에 한정.
