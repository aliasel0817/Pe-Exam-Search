# 학습노트 PDF 안정화 8차 — 원본·누락 원본 포함 전체 분할 PDF 서버 재조회 (2026-10-13)

## 1. 기준과 목적
- 기준 GitHub `main`: `bf57ec550a304800e3bb193b1c706e634a6dd7e2`, 앱 `4.6.15-pdf-relation-readback-identity`.
- PR #15, #16 병합 및 GitHub Actions 회귀검사·Pages 배포 성공 확인. PR #8 콘텐츠 전수감사는 독립 Draft/Open 유지.

## 2. 수정 사항
- 앱 후보 버전: `4.6.16-pdf-all-batch-readback`.
- `collectPendingReferencePdfRelationEntries`: 새 원본(`new-original`), 누락 보충(`missing-original`), 보강(`supplement`), 개정(`revision`) 4종 배치 모두 수집.
- `saveManagedTopic`: 분할 대기 페이지 수·색인·문서모드 일관성 및 잘못된 계속 페이지 직접 연결을 **첫 업로드 이전**에 검사하여 불완전 대기 배치의 불필요한 부분 업로드 방지.
- 모든 분할 배치를 페이지별로 업로드한 후 최신 Apps Script `pdfPageFiles` 전체 목록 재조회. 페이지토큰·페이지키·번호·Drive 파일ID 비교.
- 원본의 예상 자료유형은 `원본`. 새 원본의 `basePageKey`는 선택한 부모 폴더키가 아닌 **새로 발급된 페이지키 자체**임. 원본 행에 보강·개정 관계 필드가 잘못 기록된 경우 거부.
- 종전 보강·개정 앵커·대체대상·판본·활성상태 검증을 유지.
- 실패 시 토픽 저장 차단, 대기 파일 보존, 자동 삭제/덮어쓰기 금지. 기존 단일 1페이지 파일 직접 교체 경로는 그대로 유지.
- 파일: `study-note/study-note.html`, `study-note/tests/test_reference_pdf_multipage.cjs`, 통합 매뉴얼 v1.8, 이 체크포인트.

## 3. 자동검증 항목
- 교재 새 원본 2페이지 + 서브노트 누락 원본 3페이지: 정상 서버 재조회 총 5개 페이지.
- 자료유형이 `원본`이 아닌 경우, 새 원본의 기준키가 부모 폴더로 잘못 표시된 경우, 원본에 앵커 관계가 포함된 경우 검출.
- 서버 페이지 누락, 기존 성공한 파일ID 불일치, 분할 대기 페이지 누락, 계속 페이지 직접 연결 차단.
- 재조회 네트워크 실패 후 동일 관리창에서 재시도 가능; 대기 항목 보존.
- 불완전 배치는 첫 업로드 전 검출하여 신규 Drive 파일을 만들지 않도록 저장 순서 검수.
- 기존 PDF 분할/원본 앞뒤 이동/개정 첫 장 마지막 업로드/기술용어 관련 회귀검사 보존.
- 자동검사 **통과 여부는 실제 GitHub Actions 결과를 확인하여 확정할 것**.
