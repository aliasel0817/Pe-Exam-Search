## 1. 사용자 요청과 작업 범위

주도메인(H열)이 비어 있던 **2,574건만** 2차 의미 기반 분류해, 기술 분야를 판단할 수 있는 문제는 채우고 정말 애매한 문제만 공란으로 남긴다. 기존 주도메인 18,223개와 연관도메인(I열) 2,468개는 절대 수정하지 않는다.

기존 원본 `list.xlsx`, 원본 백업 `question-domain/backups/list-original-20261111.xlsx`, `Topic_list.xlsx`, Google Sheets LIVE MASTER, 웹 운영 소스, `main`은 변경하지 않는다.

## 2. 사용한 방법 — 3중 검증과 중복 문제 묶음

1. **다국어 의미 유사도:** 무료 공개 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` 임베딩 모델로 기존 학습 토픽·기출문제 **5,672개 참조 문장**과 H열 미분류 **2,574개 문제**를 비교. 로컬 CPU 사용.
2. **문자·기술명 분류 교차 검토:** 기존에 이미 분류된 문제 18,223개 및 학습 토픽 2,670개를 바탕으로 문자 n-gram 기반 분류기와 기술명/영문 약어 확장형을 비교.
3. **중복 문제와 의미 검토:** 반복 출제된 문제는 같은 토픽으로 묶고, 도메인 자체가 분명한 기술명·표준·프로토콜과 인접 문맥을 검토하여 잘못된 자동 추천(예: EVM, MPEG-21, QoS 등)을 수정.
4. **보수적 미분류:** 의미가 여러 개일 수 있는 짧은 약어, 제목만 존재하거나 문제 의미가 부족한 경우는 H열 공란 유지. 기존 도메인 11개 밖의 코드는 생성하지 않음.

사전 점검으로 기존 자동 주도메인을 가진 문제 **2,100건을 임시 검증 집합**으로 사용했을 때 모델은 기존 결과와 **89.2% 일치**, 비교적 신뢰도가 높은 예측 부분에서는 **93.5% 일치**했다. 이는 **기존 자동 분류값과의 재현 일치율이지 전문가 정답 기준 정확도가 아니다.**

모델은 PC 전역에 설치하지 않았고, 충돌을 피하기 위해 독립 임시 작업 폴더의 격리된 Python 환경에서 실행했다. 기존 타 채팅 프로세스는 조작·종료하지 않았다.

완전히 해석하기 어려운 **60개 문제 행**을 별도 CSV로 기록했다. 예: `SCM`, `KMS`, `CPC`, `ASP`, `Agent`, `Falcon`, `Amazon` 등 단독 기술명·약어 및 `설명하시오` 등 내용 자체가 없는 문제.

## 6. 무결성 검수

- 수정 대상: `question-domain/work/list-domain-working.xlsx`의 **기존 공란 H열 2,514개 셀만**
- 원본과 백업 파일 SHA-256 동일 확인.
- 수정 XLSX의 XML 파싱과 ZIP CRC 검사 통과.
- 수정 전후 ZIP 구성요소 목록 같고, Sheet1을 제외한 내부 10개 구성요소는 바이트 동일.
- 새로 입력한 H열 2,514개 셀만 XML에서 삭제하면 **수정 전 Sheet1 XML과 바이트 단위 완전 동일**. 기존 A~G 원문·서식·수식, 기존 H 값 및 모든 I 값 보존.
- 독립 `openpyxl` 읽기 전용 검사에서 실제 문제 **20,797행**, 최종 H **20,737건**, I **2,468건** 확인.
- 실 Microsoft Excel 앱으로 직접 여는 검수, PC·태블릿·스마트폰 UI 검수, 주도메인 정답 전수검사는 **미수행**. 파일 자동 무결성 검사와 실기기 검사를 혼동하지 말 것.
