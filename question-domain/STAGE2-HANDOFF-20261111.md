## 5. 3단계 실행 요청

사용자가 별도 메시지로 3단계 진행을 지시할 때만 아래를 수행한다.

1. GitHub 최신 main·작업 브랜치·열린 PR을 다시 확인하고 기존 커밋과 충돌을 피한다.
2. 원본·백업본은 읽기 전용으로 확인하고 수정하지 않는다.
3. 학습노트 LIVE MASTER의 최신 도메인 코드/명칭을 안전한 읽기 전용 방법으로 확인한다. `Topic_list.xlsx` 기준이 실제 최신 기준과 같은지 점검한다.
4. 실제 문제 문장(20,797행)을 기준으로 작업본 `주도메인` 열에 **실재하는 도메인 하나**를 분류 입력한다.
5. 판정이 불확실하면 근거가 있는 최선의 선택을 하되 근거 없는 코드를 생성하지 않고, 분류 불가 항목은 공란으로 남겨 집계한다.
6. 이번 단계에서는 `연관도메인` 열은 건드리지 않는다. 기존 NO/구분/회차/종목/유형/문제/년월도 수정하지 않는다.
7. 분류 정확도 100%보다 학습 참고용 전체 입력을 우선한다. 작업 노력 목표는 **값 입력 80%, 간단 검수 20%**이다.
8. 분류 완료 건수, 공란 수, 판정 기준 및 구조 검사 결과를 보고한다.
9. 브랜치에만 커밋하고, 원본/백업/LIVE MASTER/main/운영을 보호한다. 사용자 승인 없이 병합·배포하지 않는다.
10. 다음 채팅에서도 이어서 사용할 수 있는 **4단계 작업 요청서 v1.3**을 생성하여 전달한다.
