## 4. 3단계 실제 간단 검수

- 2회 자동 분류 계산 후, 대표 문제(BPR·ATAM·Jackknife·Computer Vision·VPN·컨테이너 보안 등) 표본에서 도메인 방향 검토.
- Excel 구조 읽기 확인: Sheet1 전체 20,798행/9열, Sheet2 비어 있음.
- XLSX ZIP 구성요소 11개 중, 기존 10개 구성요소가 수정 전 작업본과 바이트 단위 동일.
- 기존 Sheet1 XML에서 **신규 H열 주도메인 셀만 제거하면 수정 전 XML과 정확히 일치**함을 검증. 기존 A~G열 값·수식·서식·원문 보존.
- H열: 18,223개 코드 셀만 추가, 나머지 2,574개 공란.
- I열 데이터 셀: **0개 (완전 미입력)**.
- 원본/백업본의 SHA-256 동일. 실제 PC Excel 프로그램에서 직접 열기 실기기 테스트는 별도로 수행하지 않았음.
- GitHub 작업 브랜치로 푸시 완료, 운영 main·LIVE MASTER·서비스 배포 변경 없음.
- 독립 Windows 임시 체크아웃에서 작업. 다른 채팅의 세션과 PID는 조작하지 않았음.

## 6. 다음 작업 — 4단계 수행 지시

사용자가 이 인계서를 다음 채팅에 입력하고 별도로 `4단계 진행해줘`라고 요청하면 아래를 수행한다.

1. **변경 전** 저장소 최신 main, 작업 브랜치, 열린 PR, 사용자 변경과 미커밋 충돌을 확인한다. 브랜치는 기존 `feature/question-domain-classification-20261111`를 이어받는다.
2. 원본 `list.xlsx`, 백업본, LIVE MASTER, `Topic_list.xlsx`는 **읽기 전용**이며 수정 금지.
3. 작업본 `question-domain/work/list-domain-working.xlsx`의 실제 문제 F열과 확정된 주도메인 H열을 참조한다. H열의 사용자가 편집한 값이 있으면 그대로 존중한다.
4. **I열 `연관도메인`만 입력**한다. 주도메인 이외의 관련 분야가 명확하면 기존 코드 중 1개 이상을 입력하고, 연관 분야가 명확하지 않으면 I열을 비워둔다.
5. 여러 연관도메인이 있을 경우 순서와 구분자를 통일한다(권장 ` | `). 동일 도메인 반복이나 H열 주도메인 중복을 피한다.
6. 기존 11개 실제 코드 이외의 코드나 명칭을 만들지 않는다. 근거가 약한 항목은 무리하게 연관도메인을 붙이지 않는다.
7. **3단계 H열 18,223건 및 공란 2,574건의 원래 상태를 변경하지 않는다.** A~G열, 문제 원문, I열 헤더, Sheet2, 서식과 수식도 유지한다.
8. 분류 입력 80%, 간단 검수 20%의 노력 비율을 유지한다. 전수 정답 확인/학술 검증을 목표로 시간을 소비하지 않는다.
9. 실제 연관도메인 값 입력 건수, 공란 건수, 무손실 구조 검사 결과를 보고한다.
10. 기존 작업 브랜치에만 커밋한다. 사용자 승인 없는 main 병합·배포와 LIVE MASTER 수정 금지.
11. **5단계 작업 요청서 v1.4**를 GitHub와 **채팅 메시지 전문**에 모두 제공한다.
